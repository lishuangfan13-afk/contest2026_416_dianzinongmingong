# BES 单板最小交付计划

2026 年 10 月 30 日起，开发集中在 BES2800BP 单板。先完成真实录音和真实播放在同一固件中的闭环，再接回朝夕的 AI 与提醒能力。像素钟保留为后续显示扩展，当前交付不依赖它。编程、编译和本地联调由本地 Codex 负责，云端开发暂停，已完成的工具链资料保留。

## 当前可复用成果

| 链路 | 实物验证结果 | 当前限制 |
| --- | --- | --- |
| USB 串口与下载 | 已完成 NSH 双向交互和 AP 单分区烧录；响应正常时可安排软件重启进入下载模式 | 当前插线、端口号和在线状态需在每次联调时重新识别 |
| 板载数字麦克风 | P27 固件通过真实 PDM 与 DMA 采到近距离人声，用户确认增强后能清楚辨认内容 | 原始音量低；验证使用电脑上的 100 至 6000 Hz 滤波及 40 dB 增益，板端增益处理尚待整合 |
| 模拟播放输出 | P30 固件在 R185 下方两针接点，驱动现有 8 Ω、2 W 标称喇叭，2 秒测试音可听见 | 通过的是短时测试音；语音播放、长时间负载及额定功率没有验收 |
| 原配圆屏 | 现有屏幕持续全黑，当前按不可用处理 | 不据此认定屏幕本体已经确定损坏 |

P27 与 P30 都替换同一个 `codecprobe` 入口，目前需要换固件才能切换录音与播放。它们是两项独立成功的硬件试验，还没有构成一个可录可放的完整应用。通用 `/dev/audio` 在诊断构建中仍使用 `audio_fake`，不能把该设备节点的正常返回当成实物音频已经接通。

诊断源码和可重建镜像见 [音频诊断说明](../diagnostics/bes_audio/README.md)，试验数据见 [硬件验证记录](bringup_logs/20261027_audio_evidence.json)。

## 第一个开发里程碑

用同一份 BES 固件完成以下人工触发流程：

1. 启动进入可交互状态，串口能查询版本、空闲状态和最近一次错误。
2. 触发一次最长 2 秒的真实麦克风录音，报告采样率、样本数和完成状态。
3. 停止采集并释放输入资源，对录音做去直流、受控增益和限幅。
4. 触发回放同一段录音，输出持续不超过已试验的 2 秒，结束后静音并释放播放资源。
5. 无需更换固件，连续完成至少 3 轮录音与回放；超时或失败后能返回空闲状态并重新操作。

这一步先用串口手动触发，暂不增加唤醒词、常开监听或额外按键的硬件依赖。验收需要用户确认回放中可以辨认刚才说的话；DMA 完成日志和文件有内容只能作为辅助证据。

## 实现顺序

1. **固定基线。** 保存两份成功诊断的源码、镜像、参数和校验值，验证源码能够重建出相同镜像。
2. **统一音频程序。** 复用已确认的 PDM 引脚和 DAC 路径，使用明确的录音、处理、播放和清理流程。输入和输出先顺序运行。
3. **实物闭环。** 用户准备好后，在同一固件上进行录音与回放对照，记录实际听感、错误恢复和连续运行结果。
4. **接回作品能力。** 音频闭环稳定后，复用原有 AI Agent、记事与提醒代码，确定首个可演示的无屏场景。ASR、TTS 和联网服务按实际可用条件接入。

第一里程碑是工程最小闭环。比赛作品的最终功能验收在这个基础上确定，不能把离线回放试验直接计作 AI 语音问答完成。

## 本轮范围

当前优先完成基线归档及单板音频闭环。像素钟、双板通信、原圆屏界面重写和完整外壳设计留到单板验收之后。历史 LVGL、设备端 Skill、AI Agent 补丁及原 AI Coding 日志保留，按后续功能需要复用。

普通串口终端可以用于当前阶段的调试入口。最终是否必须脱离电脑、使用什么用户触发方式，待音频闭环通过后与演示需求一起确定。
