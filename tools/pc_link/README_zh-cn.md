# Windows 一键供网与自动语音入口

程序默认只让电脑提供网络，保持自动监听关闭。用户主动选择“开始自动语音”入口后，连接成功时才向开发板发送一次 `zhaoxi auto start`。之后由 BES 自己持续录音、判断说话与停顿、识别、处理业务并播报；电脑不逐句发送录音开始或停止命令，也不接管 ASR、模型和 TTS。

主机入口、环境预检和编排回归测试已经验证。**完整自动语音交互仍以对应固件的实板验收为准。** 使用前，板上固件需要支持 `zhaoxi auto start|stop|status`；旧固件不支持时，窗口会报告自动语音启动失败。

10 月 31 日的两分钟在场测试中，候选固件已自动完成三次回答，另有一段识别失败后恢复。本次逻辑修正版仍需对应固件的真人复测；主机测试使用明确的替身，不开启麦克风。程序不会在没有用户主动选择时后台打开监听，也不会因网络恢复而自行开启。

当前流式语音版需要同步更新开发板固件和本目录工具。新版降低串口转换开销、及时转发小 ACK，并对电脑内部的 TCP 通道禁用小包合并等待；旧转发程序可能使新固件仍然停顿。对应首声与连续性测量见 [语音响应优化](../../docs/语音响应优化.md)。

## 日常使用

1. 让电脑正常联网，接好板子供电和 USB2UART 数据线。
2. 只联网、不录音时双击 [仅共享网络.cmd](仅共享网络.cmd)。准备使用语音时，主动选择 [开始自动语音.cmd](开始自动语音.cmd)。两种入口各启动一个供网会话，已有会话时应先正常结束，再选择另一种入口。
3. 保留启动窗口。旧助手需要停机时，会先提示正在等待，并约每十秒报告一次进度；只有确认旧实例退出后才继续。自动语音入口确认板端 `accepting_speech=true` 后才提示可以提问；准备好后直接对板子说话，不用逐句点录音或发送命令。真实识别、回答和声音仍要按实际结果判断。
4. 结束时双击 [停止朝夕语音.cmd](停止朝夕语音.cmd)，等待正常结束确认，再关闭启动窗口。

一次会话默认最长一小时，到期会请求退出并检查恢复控制台。使用本机停止入口时，停止文件只通知当前供网程序；该程序会继续转发退出过程的数据，等待板端结束并清理电脑的临时转发设置。

在启动窗口按 Ctrl+C 也会先请求板端退出，继续转发停止握手的数据，收到完整退出结果后才清理连接。板端尚在退出时，窗口会显示正在停止；未收到完整确认时，不会声称停止成功。主动结束会话优先使用停止入口或 Ctrl+C。

同一记录目录已有活动会话时，入口会保留现有会话并提示先停止。已退出进程留下的历史状态不会遮住当前会话；无法读取的状态会提示检查，不能当作“没有运行”。Windows 状态文件使用完整快照替换和允许替换的共享读取，避免停止窗口读到半写入内容。

如果窗口显示“控制通信未确认”，当前不能视为自动语音可用。供网程序会继续检查网络；自动语音启动请求每个会话只发送一次，不会因网络状态变化反复启动板上的服务。

如果网络已建立但 `auto start` 返回失败，窗口会单独报告“自动语音未能启动”，保留供网方便排查。网络控制通道可达和自动语音启动成功是两项分别记录的状态。

开发板在启动过程中提前结束、返回非零错误，或退出结果没有完整读到时，程序会明确报告失败，不会因为电脑端清理完成就显示启动成功。状态记录保留板端退出码；只看到结束提示的前半行，也不会被当作正常完成。

窗口约每四秒读取一次板端状态，分别提示校准、等待说话、收音、识别、等待回答、合成语音、实际播放或错误恢复。合成阶段不声称已经开始出声；识别、回答和合成阶段持续较久时，约 15 秒后提示一次等待时间，随后约每 30 秒提示，不要求用户重复说话。它读取的是状态，不发送每句录音控制命令。状态读取失败会单独显示，不会冒充 ASR 识别错误。回答超时会显示自动监听已经停止，需要检查后主动重启。

## 自然停顿与下一句话

逻辑修正版采用约 1.2 秒连续静音判断句末。句中短于该间隔的停顿仍保留在同一句，语音检测同时跟踪环境噪声。开始自动语音后先完成一次环境校准，回答结束后复用噪声基线，避免每轮重新校准吞掉下一句的开头。

当前采用半双工：识别、等待回答、合成和播放时暂停收音，不排队收取忙时插话，也不支持打断播报。听到就绪提示、窗口确认可以说话后再问下一句。提醒抢播打断本句或语句达到长度限制时，板子等待完整停顿，再提示重新说完整的短句，避免只把句尾提交成新的命令。

## 当前电脑环境

已验证的环境为 Windows、Python 3.14、pyserial、Ubuntu-22.04 WSL，以及 WSL 中的 ppp、ip 和 iptables。WSL 网关需要能够配置自身的网络转发，当前实现使用 root 环境。

一键入口自动枚举 FTDI 串口；只有一个匹配的板子时直接使用它。找到多个时会要求明确指定，不会任选一个串口。预检只枚举端口、检查 WSL 依赖，不打开串口或录音，也不自动安装软件。

仅检查环境：

```text
python tools/pc_link/launch.py --check-only
```

指定串口及二十分钟仅供网会话：

```text
python tools/pc_link/launch.py --port COM3 --duration 1200
```

主动开启自动语音：

```text
python tools/pc_link/launch.py --auto-voice
```

显式选择只提供网络：

```text
python tools/pc_link/launch.py --manual-voice
```

也可以直接使用原供网入口；只有加 `--auto-voice` 才会启用板端自动语音：

```text
python tools/pc_link/start.py --port COM3 --auto-voice
```

命令行请求正常结束：

```text
python tools/pc_link/launch.py --stop
```

## 配置与记录

一键入口不索取或保存 Wi-Fi 密码、云端 API 密钥。模型凭据继续从板子已有配置读取。运行时会创建本机临时通道令牌及状态、传输记录，位于已忽略的 `out/pc_link`；临时令牌在退出清理时删除。

原始串口记录可能包含板上日志、工具回复和转发内容，不能作为公开材料直接上传。公开验收只整理受控测试标记与结果。状态记录中的 `ready` 确认控制通道，`auto_voice_state` 记录一次启动请求结果，`auto_voice_board_status` 记录只读实时状态。`usable_for_automatic_voice` 还要求板端近期实际报告 enabled、running 且无当前错误；`accepting_speech` 另外要求板端确认当前确实在接收语音。`enabled=false` 而 `running=true` 表示停止中，不能当作完全停止。这些字段不替代端到端语音验收。

联网与业务的已有实板证据见 [电脑网络共享](../../docs/电脑网络共享.md)。
