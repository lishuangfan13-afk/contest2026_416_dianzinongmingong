# 本地提示音、独立资讯与语音人设

本版在原热点固件上增量开发，不修改 BSP 时钟、PWM、I²C/SPI、DMA 配置或分区。仓库发布 BIN 与已验收实板的开机联网播报版本一致，镜像与 manifest 成对更新。

## 本地提示音

`app/zhaoxi/local_prompts.c` 只接受固定 ID，不接受模型或用户提供的文件路径：

| ID | 文本 | PCM 字节数 |
| --- | --- | --- |
| hello | 你好 | 46,080 |
| news_ready | 有新的资讯，需要播放吗？请说播放，或暂不播放。 | 207,360 |
| network_error | 网络暂时不可用，请稍后再试。 | 130,560 |
| network_connected | 联网成功 | 46,080 |

音频是 24kHz 单声道 16 位小端 PCM，位于 `/emmc/zhaoxi/audio/prompts/<ID>.zxp`。24 字节 ZXP1 头记录格式、长度和 CRC32；出声前校验整个文件，最多接受 480,000 字节 PCM。缺失或损坏可走原在线 TTS，一旦开始本地播放则不再回退。取消、播放错误和 Agent 退出会终止本地流。

唤醒后的“你好”和资讯询问自动命中固定文本。问答提交失败或超时可调用网络提示，最多每 60 秒一次；休眠时 ASR 错误仍使用短提示。动态答案及新闻正文继续使用在线语音；唤醒识别仍依赖联网 ASR。

开机后取得有效网络地址、语音空闲时，自动播放本地“联网成功”。每次整板启动成功播报一次；同次开机的断线重连和 Agent 重启不重复，播放后仍等待唤醒词。已有对话优先，播报失败保留待播状态，30 秒后再试；缺少或损坏该本地资产时不调用在线合成。`zhaoxi news status` 的 `boot_network_announced` 和 `boot_network_error` 可用于确认结果。

资产在 `assets/local_prompts`，不含模型密钥。正常停止 Agent、确认实际退出并关闭其他串口程序后安装：

```powershell
python tools/local_prompts.py install --port COM20 --assets assets/local_prompts
```

工具核对 manifest 和 CRC，以 1024 字节确认块传输；板端写固定 ID 的 `.part`，校验后原子替换。失败保留旧资产并恢复控制台。完成后重启或从长驻 Agent 入口启动。需要重新生成时将 `install` 改为 `prepare`，它只使用板端既有凭据生成上述固定文本，凭据仅留内存。

可用 `--id network_connected` 只生成／安装新增提示音，并保留其他资产和 manifest 记录。

板端命令：`zhaoxi prompt status`、`zhaoxi prompt play hello`。2026-11-03 初轮三段实板播放均通过，当时 WLAN 地址为 `0.0.0.0`，没有在线 TTS 请求，接收与播放字节一致。新增的第四段“联网成功”已在重启自动联网后由用户确认听到，随后恢复等待唤醒词。

## 独立资讯接口

原电脑采集器保留。新增静态 HTTPS JSON 模式，由 `.json` 路径识别，使用补丁 0068 的可取消 GET，总预算 15 秒；DNS 仍受系统解析器重试边界约束。下载不发送人设、兴趣或模型凭据。板端收到公开候选后，仍由现有 MiMo 按人设整理和保存。快照须在过去 6 小时内生成且不超前 5 分钟，文章须满足原 48 小时限制，错误内容不会作为新闻发布。

`tools/export_morning_feed.py` 复用限流 RSS 采集器，生成小于 24,000 字节的公开快照。`tools/publish_morning_feed.py` 只允许公开候选 schema，写专用 `news-site` 分支。该分支使用独立根提交，只含 `candidates.json` 与 `.nojekyll`，由 GitHub Pages 提供静态文件。采集失败不会覆盖旧快照。

`.github/workflows/morning-feed.yml` 提供每小时和北京时间 06:47 的预采集。**2026-11-03 已在用户个人 fork 的默认分支部署并启用，云端运行成功、Pages 构建完成，实板已下载并保存当日缓存。** 工作流使用 `contents: write` 更新公开数据、`pages: write` 显式请求 Pages 构建；GITHUB_TOKEN 写入本身不依赖推送事件再次触发。GitHub 调度可能延迟，七点提醒由板端时钟控制，使用提前采集的有效候选。[工作流语法](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)、[调度事件](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。

当前服务：[公开资讯 JSON](https://yuk1-r.github.io/contest2026_416_dianzinongmingong/candidates.json)。板端仅访问公开 Pages，不保存 GitHub 凭据。初始 raw 域名在本次手机网络上 TCP 连接失败，最终采用已完成实板 TLS 和下载验证的 Pages 地址。比赛主仓库未作部署修改。

工作流只有在仓库 Actions 变量 `ZHAOXI_NEWS_FEED_ENABLED=true` 时才运行；个人 fork 已启用，其他仓库合入后默认跳过。自行部署时先设置该变量并手动运行一次以创建数据分支，再将 Pages 来源配置为 `news-site` 的 `/` 并重新运行。Pages 未配置时只保存快照，若检测到来源是其他分支则拒绝重建，避免影响已有站点。

上线后先确认实际 URL 返回有效快照，再停止 Agent，用工具配置长 URL，避免 NSH 80 字节行缓冲截断：

```powershell
python tools/configure_uplink.py --port COM20 --mode wifi --news-static-url "https://你的实际域名/candidates.json"
```

该工具保留密钥、热点和其他配置，临时写入、回读、备份后替换。当前实板已切到上述真实 Pages 地址。

## 语音更新长期人设

唤醒进入问答后，说“记住，我最近在学习嵌入式”可追加人设，也兼容识别文本省略逗号；“更新我的人设为……”或“把我的人设改成……”可替换。系统先复述内容，明确回答“确认保存”“确认”等才写入。“取消”“不要保存”等保持原内容，“播放”不视为人设确认。

60 秒未确认、重新唤醒、退出或重启均丢弃待确认内容；播报失败不会进入确认状态。存储复用原 `USER.md` 原子写入、回读和备份。PC 测试不改实板初始人设；修改不会删除既有资讯缓存。
