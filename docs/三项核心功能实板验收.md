# 三项核心功能实板验收

本清单用于当前无屏 BES 固件。编译、烧录、PPP 建立、命令入队、模型回答、文件保存和实际播报分别记录；本文件不预先声明任何一项实板通过。

## 开始条件和记录

记录本次 AP 镜像 SHA256、固件构建信息、开始时间、电脑转发会话目录。只运行一个 Agent 和一个串口转发程序。转发运行期间，通过 PPP 控制通道发送业务，避免另开串口终端。

先读取板端当前时间、提醒列表、当天备忘和待办，保存为本机私有基线。验收使用本轮唯一标记，例如 `验收1031A`，不清空已有文件或提醒。

实际文件由已部署的 `note-taker` Skill 规定：

| 数据 | 默认持久位置 | 验收读取内容 |
| --- | --- | --- |
| 当天备忘 | `/emmc/zhaoxi/memory/daily/YYYY-MM-DD.md` | 日期由板端 `get_current_time` 确定；跨午夜时读取实际写入日文件 |
| 待办 | `/emmc/zhaoxi/TASKS.md` | 稳定编号及每项 `[ ]` / `[x]` 状态 |
| 长期记忆 | `/emmc/zhaoxi/memory/MEMORY.md` | 与当天备忘、待办是不同文件，不能用此文件代替两者回读 |
| 定时提醒 | `/emmc/zhaoxi/cron.json` | 使用调度工具查询，不直接覆盖文件 |

## 先验证持续通信

1. 启动 `tools/pc_link/start.py`，确认板端控制通道真实返回 `rc=0`。
2. 连续观察至少五分钟，期间定期读取时间与提醒列表；保存实际成功次数、失败和断线时间，不能只记录启动时的 `ready`。
3. 在此会话中发送一个实际问答。要求板端出现该问题对应的 `[Agent]:` 回答与成功处理记录；`command_return_only=true`、命令中的原始问题或串口中回传的数据不算回答。
4. 如链路断开，记录控制台能否自动恢复；需要恢复链路后，再继续业务验收。

## 问答

通过业务入口提交 `zhaoxi --text ask 请用一句中文解释DMA是什么`。

通过条件：得到与问题相符的真实模型回答，板端请求完成。随后使用默认语音通道再问一个简短问题，需取得 TTS 成功与实际播放记录，并由旁听者确认能听清内容。文字问答通过不代替语音问答通过。

## 记事与待办

按顺序执行，每一步等待前一步工具执行完成后回读：

1. 记录 `验收1031A 明天带学生证`。要求先读原文件，再写入当天备忘；回读能找到新记录和原有记录。
2. 查询当天备忘。回答须包括新记录，与文件一致。
3. 添加 `验收1031A 交作业` 与 `验收1031A 带水杯` 两项待办。记录工具实际写回的两个不同编号。
4. 仅完成第一项的实际编号。回读要求第一项为 `[x]`，第二项仍为 `[ ]`；编号、事项内容及其他历史记录保持原样。
5. 查询未完成待办，要求列出第二项，并且不再把第一项说成未完成。
6. 在受控重启并重新建立链路后回读上述文件，核对仍存在。该步骤验证跨重启保存；前面的当前会话回读不能代替它。

待办格式为 `- [ ] [编号] 内容` 或 `- [x] [编号] 内容`。编号范围为 1 至 9999，新编号取全部现有编号最大值加一；不因完成任务重新编号。

## 定时提醒

1. 通过自然语言请求创建约一分钟后的提醒，事项包含本轮标记。核对模型实际调用 `get_current_time` 与 `cron_add`，返回未来的触发时间和任务编号，`channel=voice`、`chat_id=zhaoxi`。
2. 查询提醒列表，确认该编号与事项存在。到期后需听见对应事项；只听见本机提示音，记为“调度与提示音通过，事项语音未通过”。
3. 创建另一条至少两分钟后的提醒，查询确认存在，再按实际编号取消。回读确认目标移除，其余提醒保留；继续观察到原定触发时间后，确认没有该提醒的出站消息和声音。
4. 单独验证 `zhaoxi remind in <秒数> <事项>` 本机直接路径。它不经过模型，须与自然语言提醒的结果分开记录。

## 一轮完整语音操作

与用户约定录音开始时刻后，录制一条明确的问答、记事或提醒口令，再停止录音。保存识别文本、实际业务处理、文件或调度回读、TTS 与播放结果。最终需由用户确认识别和播报内容正确；未进行该轮有效说话，不算语音失败或成功样本。
