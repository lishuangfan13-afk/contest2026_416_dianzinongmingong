# PPP 突发流量离线判据审计

2026-10-31。目标是判断当前 AHDLC 发送帧计数是否会把正常短时突发误判为离线。已完成限定电脑直连模式的源码修复与主机回归；修复后的真实硬件业务验收仍由后续烧录记录确认。

## 已证实的代码问题

`apps/netutils/pppd/ppp_conf.h` 定义 `AHDLC_TX_OFFLINE=5`。`ahdlc_tx()` 每发送一帧增加计数，只有收到 CRC 正确的 PPP 帧才清零；表达式使用后增，连续第七次调用触发 `ppp_reconnect()`。首次重放时的产品生命周期补丁会将这个重连请求转为接口关闭、LCP 超时和会话退出。

这项判断没有考虑经过多久。无论六帧用了 34 毫秒还是两分钟，只要尚未处理到有效接收帧，下一帧都触发离线。

主循环先尝试从 TUN 读出一帧并发送，再调用 `ppp_poll()` 处理串口输入。在远端响应尚在传输途中、或者已经收到但尚未处理完整 PPP 帧的短窗口中，发送计数仍会增加。MTU 512 下，较大的 TLS 数据会分成多帧，因而不能将七帧等同于对端故障。

## 真实源码重放

测试直接编译上游 `ahdlc.c` 与原始 `pppd.c` 加当前 0025 补丁，操作系统与对端接口使用明确的测试替身；ASan 与 UBSan 开启。

| 场景 | 结果 |
| --- | --- |
| 已收到有效 CRC 的 LCP 回复，然后连续发送六个 512 字节帧 | 六帧正常送出，计数为 6 |
| 对端下一次回复设在 100 毫秒后，第七帧在此前提交 | 立即调用真实 `ppp_reconnect`，接口关闭并标记 LCP 超时，第七帧未送出 |
| 保持相同七个帧，只将对端回复提前到第七帧之前 | 计数清零，七帧全部送出，不关闭接口 |

六帧实际编码字符数按 921600 baud、8N1 换算为约 **33.98 毫秒**。这只是编码数据的线速估计，不是实测串口吞吐、端到端往返时间或真实硬件验收。


## 对实板失败的解释范围

该重放证明当前代码存在误判正常突发的条件，尚不能证明最近的 `MBEDTLS_ERR_NET_RECV_FAILED (-0x004c)` 就由它触发。诊断固件需提供 BIO 失败时的 errno、fd、flags，以及 PPP 线程退出结果；若 errno 为接口中断且 PPP 同时因离线计数退出，因果证据才完整。

此前空闲约两分钟断线已另行定位到电脑接收线程保留了十秒 socket 超时。主机修复后持续控制链路已经延长，不能把那个已定位故障与此处的突发帧误判混为一项结论。

## 已实现的限定修复

对产品的电脑直连 PPP 会话，使用单调时钟记录最后一帧有效接收的时间，保留现有每超过 20 秒一次的 LCP Echo。在连续 **63 秒**仍未收到有效 PPP 帧时判定失联，交给现有失败退出与资源清理路径处理。判据每次主循环都会执行，因此即使应用没有发送数据也能退出；先处理已排队的接收数据，再判断期限，避免忽略已经到达的有效回复。

收到有效帧时，应在处理可能产生回复的上层回调之前更新活动时间，避免当前接收已证明对端存活却仍被旧计数误判。初始协商仍受现有 LCP/IPCP 重试以及会话所有者的协商时限约束。普通带脚本 modem 路径保留原有策略。

这项方案把失联判断改为经过时间与保活响应，而不是增加允许发送的帧数，也不会取消真实失联后的退出检测。当前 ASan/UBSan 回归已验证：七帧 512 字节突发继续发送；62 秒尚未超时、63 秒期限到达；坏 CRC 不刷新存活时间；有效回复续期；没有发送数据时主循环仍按期限返回并清理；显式停止；两种打开失败的资源清理；普通 modem 的脚本与帧计数路径保持。真实 BSP ARM 编译参数下，pppd.c、ahdlc.c 的语法检查均通过。

测试中的时间推进与系统调用是明确的替身，不代表已经完成63秒断线实测或完整语音业务验收。

## 实板 BIO 错误的新增证据

诊断版在一次真实 Agent 问答中记录：TLS 接收返回 `-0x004c`，保存的 errno 为 **107**，fd 为 7，`F_GETFL=3`、flags_errno=0。实际 NuttX `include/errno.h` 将 107 定义为 **ENOTCONN**。因此这是“socket 已不在连接状态”，并非本次 `F_GETFL` 检查时描述符不存在；不能从该信息单独断言是远端断开或本地接口关闭。

同次握手不足 0.85 秒的板端发送记录包含 14 帧 TCP，其中有连续 ACK 与握手数据的发送及重发。它与按发送帧数判离线的缺陷相容，仍需修正版实板对照或接口退出原因补齐因果证据。此时尚未完成 HTTP 请求，工具列表与模型参数不能解释这次 TLS 握手失败。
