# 本地记事

明确的 `note` 命令直接写入本机当日备忘，不再交给模型选择工具。补丁 `0057` 还将 [有限的明确中文指令](本地中文指令.md) 直接路由到同一存储模块；未命中的问答和自然语音记事继续进入原 Agent 流程，副作用请求仍受本轮写入成功证据检查保护。

```bash
zhaoxi --text note add 明天带学生证
zhaoxi --text note list
```

`note <内容>` 与 `note add <内容>` 相同。`--text` 操作不需要启动 Agent，也不调用模型、ASR 或 TTS；时钟必须已经有效。去掉 `--text` 后，入口先检查 Agent 消息总线，保存或读取成功后，将实际结果提交到语音输出通道。语音合成或播放仍取决于其服务与音频链路，存储结果以 `NOTE_RESULT` 和本地回读为准。

## 保存和确认

文件位于 `/emmc/zhaoxi/memory/daily/YYYY-MM-DD.md`。同一次操作只使用入口取得的一次 UTC 时刻，并沿用 `zhaoxi_note_path` 的固定 UTC+8 北京日期规则，避免零点附近写入与回读分别落在不同日期。未授时或时刻超出产品允许范围时拒绝操作，不创建 1970 年记录。

每条内容最多 511 个 UTF-8 字节，不接受控制字符；每日文件上限 64 KiB。新记录采用 `- 内容` 的一行格式追加。原文件即使没有末尾换行也保留原字节，只在新记录前补换行；不会通过全文件替换重写旧记录。

成功确认需要依次完成追加写入、`fsync`、回读原有前缀和本次新增记录、核对路径对应的文件身份与大小、关闭文件。只有这些步骤全部成功，才返回“已记录并读回确认”。串口回执示例：

```text
NOTE_RESULT op=add rc=0 verified=1 uncertain=0 bytes=... path=...
```

写入、同步或关闭失败可能已经留下本次记录的部分或全部内容。失败时返回未确认状态，提示先查询今日备忘，避免盲目重试造成重复；实现不会在失败后截断文件回滚，因而不会为撤销新记录而删除已经存在的内容。

`note list` 直接读取当日 `daily/` 文件，不让模型生成清单。当天文件不存在时返回“今天还没有备忘”。SDK 最近记忆仍兼容旧的扁平日期文件；此命令查询的是当前规范下的当日 `daily/` 文件。

## 并发范围

本地 `note add/list` 共用应用互斥锁。重叠操作立即返回忙状态，不无限排队；调用方可在当前操作结束后重试。文件保留和读回验证覆盖本地入口的并发操作。

SDK 的自然语音记事仍使用通用 `write_file/edit_file`，这些工具没有与应用共用的文件锁。应用追加会检查回读结果，但不能阻止另一个工具在随后重写文件。整机演示应等上一条记事请求结束后再发下一条；通用工具共享锁或专门的追加记事工具属于后续独立改进。

## 检查

```bash
python3 tests/headless/check_journal.py

python3 tools/check_headless.py \
  --agent-root /root/vela/packages/ai_agent \
  --arm-prefix /root/vela/prebuilts/gcc/linux-x86_64/arm-none-eabi/bin/arm-none-eabi-
```

独立存储检查使用实际 `journal.c`，覆盖中文记录、旧前缀逐字节保留、无末尾换行、清单读取、时间和容量边界、短写、写失败、读失败、回读不一致、同步失败、关闭失败、忙状态及时返回和八个并发追加。命令检查验证 `--text` 在 Agent 未启动时仍可本地保存，语音结果只走 outbound，明确记事不向模型消息队列提交。

存储检查使用实际文件和失败注入。BES 实板已完成新增备忘保存、旧记录保留和当天文件回读；完整固件及整机检查记录见 [构建与验收](BES固件构建与验收.md)。
