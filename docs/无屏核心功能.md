# 朝夕无屏首版功能

首版只完成问答、记事与待办、定时提醒。BES 单板负责现有音频输入输出，功能层复用原 AI Agent、工具和调度器。原圆屏界面退出当前构建，像素钟、飞书、微信、早报和健康提醒留待后续。

## 三项核心功能

| 功能 | 用户输入示例 | 实际行为 | 验收 |
| --- | --- | --- | --- |
| 问答 | 解释一下什么是 DMA | 现有识别入口取得文字，交给原模型处理，经原语音通道返回简短回答 | 内容对应问题，网络或模型失败有明确反馈 |
| 记事与待办 | 记一下明天带学生证；添加待办交作业；完成第二项 | 先读已有记录，保存备忘或带稳定编号的待办；支持查询与完成 | 回读确有新增或目标状态变化，其他记录保留，工具失败不声称成功 |
| 定时提醒 | 十分钟后提醒我交作业；查看提醒；取消这个提醒 | 获取真实时间并调用调度工具；到期直接送往 voice 通道 | 创建、查询、取消准确；到期听见对应事项，不依赖屏幕文件 |

首版支持一次性和固定间隔提醒。每天固定时刻仅在框架已应用 daily 支持且工具 schema 包含该能力时开放；不会用每 24 小时冒充每天同一时刻。

## 交互入口

正常使用时主动选择 Windows 的“开始自动语音”入口，或在网络和助手就绪后执行 `zhaoxi auto start`。板子自行检测说话和停顿，完成识别、处理、播报后继续等待下一句；不需要逐句发录音命令。结束用 `zhaoxi auto stop` 并确认 `zhaoxi auto status` 的 enabled、running 都为 false。具体停顿、提示音、忙时说话和超长语句规则见 [语音交互收尾](语音交互收尾.md)。

下面的手动录音入口用于开发诊断。`zhaoxi status` 仅表示消息总线状态，不能代替网络和语音结果：

```text
ai_agent --headless &
zhaoxi listen start
zhaoxi listen stop
```

录音结束后由原 ASR、Agent 与语音输出链路处理。还可以用串口提交相同业务：

```text
zhaoxi ask 什么是DMA
zhaoxi note 明天带学生证
zhaoxi note list
zhaoxi todo add 交作业
zhaoxi todo list
zhaoxi todo done 2
zhaoxi remind 十分钟后提醒我交作业
zhaoxi remind list
zhaoxi remind cancel a123b456
```

zhaoxi 的默认输出通道为 voice。加入 --text 可以将调试回复发到串口，例如 zhaoxi --text ask 你好。请求已提交表示进入消息队列；已记下、已完成、已设置必须来自工具执行后的真实结果。

## 旧代码处理

纯显示代码包括圆屏布局、触摸键盘、卡片、字体和 LVGL 主循环，移至 legacy/display，当前不链接、不启动。旧界面里的消息提交逻辑改为 zhaoxi 命令直接连接原 Agent 消息总线，避免继续依赖 CHAT_IN 和 CHAT_OUT 文件中转。

笔记和待办数据格式、模型配置、语音服务、cron 引擎继续复用。提醒资产从写 REMINDER.md 改为 channel=voice。出厂 cron 列表为空，移除自动早报、久坐、喝水和早安任务。无屏配置只安装和发现 note-taker、reminder 两项业务 Skill；设备上残留的旧扩展文件不会进入当前 Skill 摘要。

## 构建和部署

1. 更新 repo manifest，启用 app/zhaoxi，移除旧 zhaoxi_ui 链接。旧工作区还留有 packages/zhaoxi_ui 链接时，应在确认链接目标后移除该旧链接。
2. 应用完整的当前 SDK 补丁序列，支持 --headless、BES 实际音频、MiMo 语音、可靠存储及网络生命周期。当前产品要求 --headless；非产品配置保留原 CLI。
3. 合并 configs/bes_headless.fragment。保留已经验证的音频后端、采样和供电设置。
4. 0009 提供可选的开机后台启动；第一次部署也可以只使用 0008，从串口手动启动。旧 0004 显示启动补丁和 0006 显示状态文件补丁已归档。
5. 配置原模型及语音服务。若 Agent 已在后台运行，先执行 zhaoxi stop，等待日志出现 Shutdown complete；若在原 vela> CLI 中，使用 quit 并等待同样的停止日志。不要在仍运行的 Agent 上覆盖调度文件。
6. 使用 tools/deploy_assets.ps1 部署六个核心资产。本无屏配置数据根目录为 /emmc/zhaoxi，传入 -BaseDir /emmc/zhaoxi。脚本替换资产路径、回读校验，保留已有 MEMORY.md 和 cron.json。
7. 部署完成后运行 ai_agent --headless &，让 Skill 和 cron.json 从新文件加载。若已自动启动，不要再次启动第二个实例；当前代码会拒绝重复启动。

当前使用真实 exFAT 挂载，已经验证记录跨 RESET 和 AP 固件更新保留。部署默认不替换已有调度列表；历史 tmpfs 固件仍不能提供断电保留。

## 检查与实物验收

主机检查覆盖命令路由、UTF-8 内容、缺参和超长输入、队列满、Agent 未启动及停止后的失败返回，并用真实上游消息总线实现执行。语音硬件调用在主机测试中使用明确标注的测试替身，不把它算作录音、识别或播报验证。

功能入口有 ARM 对象检查，另外已经在实际 BSP 中链接和烧录完整 headless_r10 固件。资产覆盖持久根目录与两种历史根目录。工具层和调度器的实板结果、完整语音业务尚未通过的部分，见 [固件构建与验收](BES固件构建与验收.md)。

实物验收顺序为：一次问答；新增并查询一条备忘；添加两项待办并只完成指定一项；创建一个短时提醒并听到播报；取消另一个提醒后确认不再触发。遇到识别、模型、文件写入或播放失败时，应返回失败，不能输出成功确认。

## 不依赖模型的本机提醒

R10 的 BES 配置可以从串口直接创建、查询和取消提醒，不调用 ASR 或模型：

```text
zhaoxi remind in 60 喝水
zhaoxi remind list
zhaoxi remind cancel <返回的八位编号>
```

秒数为 1 至 31536000 的整数。时钟未校准、保存失败或容量已满时不确认创建。`--text remind in ...` 到期输出串口文字；默认提醒在网络与语音可用时播报，否则尝试两秒本机提示音，同时输出提醒文字。提示音不代表已播报事项内容，播放器错误也会报告。调度器按最近的到期时间唤醒；队列拥堵时尚未投递的一次性任务保留重试。

实板已验证创建、查询、单项取消、三秒提醒在五秒观察窗口内投递并移除。音频后端此前已有用户听感确认；新到期提示音路径的主观听音以单独记录为准。

R10还实测了断网提醒到期后的真实DMA/DAC输出：两秒提示音写入全部完成，一次性任务移除。该次用户主观听音尚未确认，不将其等同于云端播报事项内容。
