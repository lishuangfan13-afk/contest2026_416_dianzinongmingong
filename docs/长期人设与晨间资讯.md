# 长期人设与晨间资讯

需要包含补丁 0065、0066 的新固件。2026-11-02 发布的 [AP 镜像](../firmware/headless_pc_link/nuttx_ap_headless.bin) 已包含本功能，实测范围见 [本轮验收](2026-11-02唤醒与晨间资讯验收.md)。

## 默认体验

板上 `/emmc/zhaoxi/config/USER.md` 保存用户明确设置的人设。普通长期事实继续使用现有 `memory/MEMORY.md`，资讯独立保存在 `news/brief-YYYY-MM-DD.json`，三者互不混写。更新人设会保留上一版 `USER.md.bak`，新文件经过同步和回读后才替换。

每次联网或恢复连接后校准 UTC：电脑供网使用电脑时间，独立联网尝试 SNTP。只有授时成功才执行每日任务；调度按北京时间。06:55 预取，07:00 起在空闲且未唤醒时询问；当天错过七点，在 22:00 前联网会补取。22:00 后不主动发声。没有相关新资讯时不询问。

首版采集 Hugging Face、Espressif、Raspberry Pi 官方 RSS，取最近 48 小时的少量候选。板端读取人设，用 MiMo 选取最多三条并生成中文摘要；数量不足时少推。标题、原文链接、来源和时间由候选原样保留，模型只能填写摘要与相关性。候选只传兴趣类别，完整人设与 API Key 不发送给采集器。

资讯先写入板子，再播报询问。回答“播放”“需要播放”“要听”等明确许可后，才朗读当前批次；“暂不播放”“不要播放”“不听”等拒绝优先。60 秒未收到明确许可，不播放并返回等待唤醒。等待许可时无需唤醒词；重新说“你好，夕夕”会取消本次许可等待并进入普通问答。

同一批次每天最多自动询问一次。许可只保存在内存，重启后不会自动续播；播放进度保存在文件中，明确再次请求时从未完成的条目继续，全部播完后再次请求会重播。缓存保留 30 天，已出现的旧链接不会作为次日新资讯重复推送。

## 设置与检查

电脑供网启动后，采集器随 Linux 网关自动启动，监听 `10.254.42.1:8766`，随会话结束关闭。先设置人设，再设置资讯接口：

```powershell
python tools/pc_link/control.py --set-profile "热爱 AI、电子技术的大学生，偏好中文、开源项目与动手实践。"
python tools/pc_link/control.py --profile
python tools/pc_link/control.py --cmd news endpoint http://10.254.42.1:8766/candidates
python tools/pc_link/control.py --news
python tools/pc_link/control.py --news-get
```

`--news` 显示授时、阶段、缓存、是否询问、是否拒绝及播放进度。`--news-get` 回读当天完整内容与来源。接口地址、人设和缓存均保存在板上，断电保留。修改人设不会重写当天已生成的批次，次日生成时使用新版本。

调试可执行 `--cmd news fetch` 请求生成当天资讯，`--cmd news ask` 显式再次询问。已有当天批次时不会重复生成或覆盖。正常语音操作为“你好，夕夕”后说“播放今天的新闻”；这句话本身是明确播放许可。命令 `--cmd news play` 也代表操作者明确许可，`--cmd news decline` 可在等待许可时拒绝。

串口控制台可用 `zhaoxi profile show`、`zhaoxi profile set <人设>`、`zhaoxi news status`；供网期间串口由转发程序占用，统一使用 `control.py`。

## 当前边界

本版缓存文字，识别、摘要和朗读需要网络。采集器目前运行在电脑上，接手机热点后还需将其迁移到持续可达的服务，并设置 HTTPS 接口；公网域名接口仅接受 HTTPS。现有电脑会话最多一小时，不能据此宣称已经支持整夜无人值守，常驻供网按后续计划处理。

播报采用半双工互斥，播放中暂停麦克风。本版不支持边播放边语音打断。资讯接口、模型或语音服务失败时保留已存内容，不凭空生成新闻；抓取每天最多自动重试三次，每次间隔五分钟。询问输出失败也不会自动反复发声，可在恢复后用 `news ask` 重新询问。
