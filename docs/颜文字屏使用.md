# 颜文字屏主机桥

主机桥把朝夕的运行状态映射成七种固定表情与时钟页面，由 EasyMatrix 32×8 像素屏显示。它通过 CH343 串口控制像素屏，通过电脑上的只读会话状态和状态查询了解 BES 的进度，不连接 BES 的 FTDI 串口，也不会开启麦克风。

入口是 [启动颜文字屏.cmd](../tools/pc_link/启动颜文字屏.cmd)，实现位于 [display_link.py](../tools/display_link.py)。这是独立窗口，不改变原来的电脑供网或自动语音入口。

## 启动

准备好 Python 3 和 pyserial，并连接运行新版 `zhaoxi.display` JSON 协议固件的 EasyMatrix。主机桥默认只选择唯一的 CH343（USB VID `1A86`、PID `55D3`）；当前屏控制板通常枚举为 COM4，实际端口以本机枚举为准。

屏幕冷开机可能先连接 Wi‑Fi、等待 NTP；主机桥默认最多自动等待 70 秒，只提示一次，失败探测之间等待五秒，确认就绪后立即继续，无需 RESET。可用 `--boot-wait-seconds 0` 关闭重试，允许范围是 0 至 90 秒；明确的协议错误或旧 CLI 菜单会立即失败，不等满时限，也不回显原始启动日志。

单独测试一个表情：

```powershell
python tools/display_link.py --port COM4 --show listening
```

该测试显示五秒，然后请求恢复时钟；可用 `--hold-seconds 10` 延长到十秒，允许范围是 0 至 30 秒。没有启动或查询 BES，不需要先开麦克风。

跟随正常供网会话：

```powershell
python tools/display_link.py
```

也可以双击 `tools/pc_link/启动颜文字屏.cmd`。默认在仓库 `out/pc_link` 中选择最新的、主机进程仍存在的活动会话。先启动原来的供网窗口，再保留颜文字屏窗口即可；没有活动会话时显示时钟。

如果供网使用了其他状态目录，指定同一个根目录：

```powershell
python tools/display_link.py --session-root "<供网状态目录>"
```

要固定跟随某一会话目录：

```powershell
python tools/display_link.py --watch-session "out/pc_link/<会话目录>"
```

`--port` 只能选择 CH343，显式填入 BES 的 FTDI 端口也会被拒绝。存在多块 CH343 时必须明确指定。结束用 Ctrl+C；程序请求屏幕恢复时钟后关闭 CH343。要用其他串口工具或更新屏控制板固件时，先结束这个窗口释放端口。

## 状态含义

| 屏状态 | 触发来源 |
|---|---|
| `idle` | BES 会话可用，当前没有收音、处理或播放活动 |
| `listening` | 板端报告正在接受说话、收音或校准 |
| `thinking` | ASR、等待助手、合成语音、文字请求开始，或输出准备中 |
| `speaking` | 板端报告实际播放；文字触发的 TTS 同样显示，独立于自动语音开关 |
| `success` | 明确的记事／待办／喝水提醒／定时提醒成功回执或请求结束，短时显示 |
| `error` | 明确业务错误或状态查询失败；RPC 连续失败两秒后回到时钟 |
| `sleep` | 已启用唤醒功能，但设备尚未被唤醒；文字播放等实际输出可覆盖它 |
| `clock` | 没有活动会话、活动会话结束、RPC 持续失败或桥接程序退出 |

播放状态优先于请求完成的短时提示，避免模型刚生成完回答就一直显示“成功”，实际还在播报。业务反馈保留三秒；短时反馈后回到实时状态。

## 读取哪些数据

程序只读取所选会话的 `status.json`，以及启动桥接后新增的 `serial_private.bin` 字节。原始文件保持在本机、不修改。日志只提取 ASCII 运行事件：trace BEGIN／END、`TODO_RESULT`（兼容 `TO_DO_RESULT`）、`NOTE_RESULT`、`DRINK_RESULT`、Reminder 与 `REMINDER_DELIVERY`；业务回执仅按数字 `rc=0`／非零映射成功／错误，不提取路径或正文。不把用户问题、回答、备忘内容、录音或凭据发到屏上，也不把原始串口行打印出来。

板端自动语音状态通过既有 `control.request()` 查询，发送内容只有 `{"action":"auto-status"}`，请求超时参数为两秒。最多一个后台查询在途，约两秒一次，不发送 start、stop、listen 或命令消息。慢查询不会阻塞屏幕租约续期。

程序优先使用新版状态里的 `wake_enabled`、`awake`、`output_active`、`output_playing`。其中输出字段不依赖 `enabled`，所以关闭自动收音后，明确的文字播报仍会显示输出状态。

## 串口协议与确认

串口为 115200、8N1、无软件或硬件流控，打开前设置 DTR、RTS 为 False。每条请求为不超过 192 字节的 ASCII JSON，以 LF 结束：

```json
{"id":1,"cmd":"ping"}
{"id":2,"cmd":"status"}
{"id":3,"cmd":"emotion","state":"thinking","ttl_ms":10000}
```

桥接启动时先完成 ping 和 status 握手。确认必须包含 `type="zhaoxi.display"`、整数 `v=1`、匹配的请求 ID／命令、`ok=true`、有效 state／active／frame／uptime_ms，以及设备 `EasyMatrix`、宽 32、高 8。emotion 确认的 state 必须与请求一致，不能仅凭串口写入成功就当成已显示。屏端应在实际刷新画面后再发送 ACK。192 字节上限用于主机请求；ACK 另有固件版本、基础页和租约等字段，主机以 512 字节上限接收，并允许这些附加字段。

状态变化时更新画面；不变化时每五秒续期，租约为十秒。如果主机程序意外停止、线缆断开或退出时收不到恢复确认，屏端租约到期后恢复时钟。

原像素钟若仍运行旧 CLI 固件，主机桥会明确提示没有收到 JSON 确认或协议不匹配，然后退出。这个工具没有刷写或自动修复屏固件的功能。

## 离线回归

[tests/display](../tests/display/) 使用假 Serial、假 RPC 和临时会话文件验证协议、状态映射、增量日志以及退出恢复。测试不打开任何真实串口或麦克风；实际屏幕是否刷新，仍需匹配固件和实物 ACK 验证。

```powershell
python -X utf8 -m unittest discover -s tests/display -v
```

2026-11-02 最终离线回归为 53 项通过，包含生产 ESP 完整 ACK 的长度边界、短写不重发、只读查询、失效会话、十二秒虚拟续租和退出恢复；另覆盖记事及喝水提醒回执的成功／错误反馈与正文隔离，以及冷启动延迟、七十秒总预算、错误协议立即退出和参数范围。硬件刷写与真人画面验收由实物联调另行记录。
