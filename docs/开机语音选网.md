# 开机语音选择联网方式

本功能在联网之前使用板端个人训练的 MFCC/DTW 语音模板判断“有线连接／无线连接”，不是通用 ASR。选网询问、“连接成功”和“连接失败”均从 eMMC 的三个本地 ZXP 提示音播放；不会先连接热点调用云端 ASR，也不会调用在线 TTS 生成开机提示。已有设备模板已完成训练与独立验证，无需重录。

## 使用

1. 启动开发板，听完“选择有线连接还是无线连接”。
2. 回答“无线连接”：只连接已保存的手机热点。当前实板验证环境为 5GHz、WPA2-Personal。
3. 回答“有线连接”：通过 USB2UART 与电脑上的待命程序建立 PPP，电脑必须已联网。
4. 选定接口有效且外网往返验证成功后，本地播放“连接成功”，随后启动正常唤醒监听、提醒和晨报服务。选网成功不代表任一特定云模型服务始终可用。
5. 连接失败播放“连接失败”并重新询问，可改选另一种方式。未知语句、静音或录音错误不会连接任何默认网络；继续等待，完整询问至少间隔 30 秒，避免噪声触发连续播报。

提示音播放前完整读取并校验短 PCM 文件，再从内存送往播放器，避免在每个音频块之间读取 eMMC。正常问答继续沿用原有云端 ASR／TTS；新增本地识别只用于开机两条选网指令。

## 个人离线模板

这是每类三个样本的有限指令识别，不是通用中文 ASR。现有设备已录制并通过独立的有线、无线及无关语句验证，无需重新录制。换使用者或更换录音环境时应重新评估，不能承诺任意用户准确率。

仅在 Agent 完全停止后进行首次录入。每条 learn 命令只增加一份样本；每类执行三次，完成后 calibrate，并各做一次独立 validate。最后 `status` 必须为 `wired=3 wifi=3 calibrated=1 validation=7 ready=1`：

```text
zhaoxi stop
zhaoxi uplink-voice status
zhaoxi uplink-voice learn wired
zhaoxi uplink-voice learn wifi
zhaoxi uplink-voice calibrate
zhaoxi uplink-voice validate wired
zhaoxi uplink-voice validate wifi
zhaoxi uplink-voice validate unknown
zhaoxi uplink-voice status
```

每次等本地提示结束后再说话。`validate unknown` 要说无关语句，例如“今天天气怎么样”。`test` 只评估、不写模型。`reset` 会清除训练，不应用于已配置设备的常规故障恢复。

模板仅保存在 `/emmc/zhaoxi/audio/uplink/commands.bkw` 及备份中，包含个人语音特征，不保存原始录音、不上传、不提交公开仓库。模型读写验证版本、长度、端序、CRC 与有限数值；保存采用临时文件、同步、回读和替换。

## 配置与资产

新板除原业务资产和服务凭据外，还需要下列新增提示音、就绪的个人模板和启用配置；仅安装原有 hello 等提示音或烧入固件不足以完成部署。

在现有运行配置中设置字符串 `uplink_choice_enabled="true"` 启用。关闭时保留旧 `uplink_mode` 启动方式。配置更新必须沿用安全配置工具的停止、备份、回读及原子替换流程，不能覆盖其他配置键。当前 `tools/configure_uplink.py` 没有启用选网的 CLI 参数，也没有通用的一键模板安装／迁移工具；提示音安装、个人模板录入与安全启用配置需要分别完成。

下表前三个是开机必需资产，后三个用于首次训练／独立验证。开机资产缺失或模板未就绪时启动失败并保持离线，不会回退云端识别：

| ID | 内容 |
| --- | --- |
| uplink_choose | 选择有线连接还是无线连接 |
| uplink_ok | 连接成功 |
| uplink_fail | 连接失败 |
| learn_wired | 请说有线连接 |
| learn_wifi | 请说无线连接 |
| learn_unknown | 请说一段其他的话 |

可用 `tools/local_prompts.py` 的 `prepare`、`install` 分别生成和安装。下面以新增开机三段为例（`COM20` 换成实际端口）；首次训练还需用同样方法部署 `learn_wired`、`learn_wifi`、`learn_unknown`：

```powershell
python tools/local_prompts.py prepare --port COM20 --assets assets/local_prompts --id uplink_choose --id uplink_ok --id uplink_fail
python tools/local_prompts.py install --port COM20 --assets assets/local_prompts --id uplink_choose --id uplink_ok --id uplink_fail
```

安装位置为 `/emmc/zhaoxi/audio/prompts/<ID>.zxp`，工具校验 manifest、CRC 和板端回读。准备阶段需联网调用已有 TTS 服务生成固定资产；实际开机播放完全本地。先停止 PC 待命／供网并确认 Agent 退出，保留原有 hello、news_ready、network_error、network_connected 资产。随后按上节完成板端个人录入和验证，最后安全启用配置。现有设备已安装并就绪，不需重复生成、上传或重录。

## 电脑待命

环境要求与 [电脑供网入口](../tools/pc_link/README_zh-cn.md) 相同。电脑端只在收到完整有线选择标记或 CRC 正确的 PPP LCP 请求后接管串口；无线选择不会启动 PPP。它先释放自己的串口句柄，再启动 `start.py --boot-attach`，后者不发送 NSH 命令、不停止或另启 Agent，也不控制开机自动语音策略。

```powershell
python tools/pc_link/launch.py --check-only
python tools/pc_link/boot_watch.py --port COM20 --state-dir out/pc_link_boot
python tools/pc_link/boot_watch.py --state-dir out/pc_link_boot --stop
```

第一条正式待命命令需要持续运行；停止命令在另一个窗口执行。boot attach 默认持续直到正常停止；旧手动供网入口仍有 60～3600 秒时限。不要同时开启两个串口所有者。烧录、串口调试或模型录入前必须先正常停止待命与供网，确认串口和转发规则清理。

运行状态、子会话日志和临时通道令牌保留在本机工作目录，不得打包公开；分享诊断仅提取白名单事件和清理状态，不输出 private.json 或未经筛选的串口内容。

离线检查分别覆盖：实际 C 分类器、模型与音频 IO、选网状态机、PC boot attach、PC 收发绝对截止、晨报与新闻播放回归。合成测试不代表真实语音准确率或实板供网已通过。

BES 使用既有 WSL 构建目录增量编译，仅烧 AP 地址 `0x30190000`；不刷 BL／OTA、不格式化 eMMC。实板验收必须包含选择前离线、有线／无线成功、失败重问、未知语句拒绝、停止与资源回收、个人模板和原有配置／人设／新闻保全。发布镜像仅在本轮实板验收完成后更新。

## Windows 登录后自动待命

首次配置或换电脑时，在仓库根目录运行：

```powershell
python tools/pc_link/boot_startup.py --install --port COM20 --state-dir out/pc_link_boot --start
python tools/pc_link/boot_startup.py --status
```

工具注册当前用户登录触发、最低权限的 Windows 计划任务，不保存密码。`--start` 会立即请求启动同一任务，省去本次重新登录。安装状态只证明任务配置，不代表网络已连接；只有板端明确选择有线才建立 PPP。安装过后，平时无需手动运行 CLI。

维护时正常停止，或取消登录自动待命：

```powershell
python tools/pc_link/boot_startup.py --stop
python tools/pc_link/boot_startup.py --uninstall
```

`--stop` 停止本次 watcher／子供网会话但保留登录任务；`--uninstall` 先正常停止并确认清理，再删除任务。停止需确认串口与网关清理；清理未确认时卸载保留任务并报告失败。移动仓库或更换 Python 前，应先在原路径卸载，再从新位置安装。无线模式的待命程序周期性只读监听短窗口，调试前仍应先停止。

`--start` 现在等待真实实例在调度请求之后更新心跳，并验证端口、实例编号、进程与串口／子进程状态；旧失败文件或成功的 `/Run` 回执都不足以说明待命。`--status` 分别显示安装及实际运行状态，不代表开发板已能访问互联网。

若上次供网缺少完整退出回执，待命会保留失败状态并拒绝自动接管。确认原子进程结束、电脑串口和网关清理已完成后，可显式运行：

```powershell
python tools/pc_link/boot_watch.py --recover --port COM20 --state-dir out/pc_link_boot
python tools/pc_link/boot_startup.py --install --port COM20 --state-dir out/pc_link_boot --start
```

恢复命令使用原 state 目录和精确 session 校验；通过新随机挑战确认 NSH 响应、回读 `ppp_running=0`，再次确认维护串口关闭后才允许重新待命。旧 child 失败回执和日志保持原样，另存独立恢复证明。它不会发送复位、结束其他进程、绕过未确认的串口／网关释放，也不会自动替用户选择网络。维护串口本身关闭失败时会记录为未释放，禁止下一次恢复再次打开。电脑／板端未恢复到这些条件时需要继续排查，不能删除状态文件假装清理成功。

state 默认是仓库下 `out/pc_link_boot`，自定义相对路径按安装命令的当前目录解析并保存绝对路径。已安装时 `--stop` 自动读取任务记录的路径，显式传入不同路径会拒绝；`--status`、`--uninstall` 不接受 `--state-dir`。直接启动 `boot_watch.py` 时则必须使用同一 state 路径停止，不能用另一个空目录的“未运行”结果代替清理确认。watcher 的 `watch.json` 和 `attach.log` 位于该目录，子会话在 `sessions/<会话编号>`；旧手动入口默认状态在 `out/pc_link`。`control.py` 通过固定 PPP 控制地址访问板端，不接受 `--state-dir`；停止和清理使用 watcher／登录任务入口。
