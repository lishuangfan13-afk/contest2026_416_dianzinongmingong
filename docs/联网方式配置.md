# 联网方式配置

朝夕产品固件默认使用电脑提供的网络。板子开机后，Agent 等待串口 PPP 或其他已经建立的网络，不会自动调用 BES Wi-Fi 重连。电脑可以稍后启动共享网络；等待期间的记事、待办和本机提醒仍由原业务入口处理。

这个默认值从 SDK 补丁 `0056` 开始生效，只适用于 `CONFIG_EXAMPLES_ZHAOXI` 产品配置。通用 AI Agent 配置保持原有自动联网行为。

## 选择模式

模式保存在板端 `/emmc/zhaoxi/config/config.json` 的顶层字符串字段 `uplink_mode`。配置文件同时包含服务凭据，修改时应保留其他字段，不要用下列片段覆盖整个文件。

| 字段值 | 产品固件行为 |
| --- | --- |
| 未设置，或 `"pc"` | 等待 PPP 或已有网络；网络掉线后继续等待，不自动调用 Wi-Fi 重连 |
| 精确的 `"wifi"` | 使用已保存的 Wi-Fi 配置，保留原有启动重试和掉线重连 |
| 空值、其他字符串或非字符串 | 按默认电脑供网模式处理 |

显式选择电脑供网的字段为：

```json
"uplink_mode": "pc"
```

需要恢复自动 Wi-Fi 时，将同一个字段改为：

```json
"uplink_mode": "wifi"
```

`wifi` 区分大小写，不带前后空格。设置该字段不会配置热点名称或密码；自动 Wi-Fi 仍使用原来保存的凭据。

Agent 在联网线程启动时只读取一次模式。应先通过正常入口停止 Agent，修改运行配置，再重新启动 Agent。运行中的配置修改不会改变该实例的重连策略；重启整块板子也会重新读取。

电脑模式不关闭无线接口、不删除 Wi-Fi 凭据，也不切换已有路由。已经手动连好的 Wi-Fi 仍可使用，显式 Wi-Fi 配置和连接命令也保留。若同时存在 PPP 和 Wi-Fi，仍由原网络路由配置决定实际出口。

## 配置手机热点（无需编译）

包含补丁 0056 和 0066 的现有固件已支持保存热点、开机重连和 SNTP 授时，只需设置运行配置。本次 BES2800BP 实板与手机热点使用 **5GHz、WPA2-Personal** 完成语音验收；同一现场的 2.4GHz 连接虽可关联和授时，音频上传不稳定。频段支持应按实际开发板确认。先正常结束电脑供网会话，等待它确认板端 Agent 退出并释放串口；若未运行供网，在串口执行 `zhaoxi stop` 并等到 `Shutdown complete`。不要在 Agent 仍运行时改写配置。

关闭其他串口终端后执行：

```powershell
python tools/configure_uplink.py --port COM20 --mode wifi --ssid "你的热点名称"
python tools/configure_uplink.py --port COM20 --status
```

密码由隐藏输入提示读取，不放在命令行。自动脚本也可通过进程环境变量 `ZHAOXI_WIFI_PASSWORD` 提供，用后清除该变量。脚本只在内存处理完整配置，保留模型、凭据及其他字段；在板上写临时文件并回读，再保留 `config/uplink.bak` 和替换当前配置，不把完整配置或密码写到电脑日志。

出现 `verified: true` 后重启开发板，或在 NSH 运行 `ai_agent --headless &`。等待启动日志 `Automatic uplink: wifi`、`WiFi connected`，再执行：

```text
ifconfig wlan0
zhaoxi news status
zhaoxi --dns-info
```

应看到无线地址及网关，晨间服务状态为 `time_synced: true`、`time_source: SNTP`。无 `ppp0` 时 NSH 查询该接口会报不存在，这是未启动电脑供网的预期结果。热点掉线时固件会按原联网线程每 15 秒检查并尝试重连；首次启动等待约 3 秒再尝试，关联和 DHCP 还需额外时间。授时失败每 60 秒重试，只有成功才确认已同步。

切回电脑供网时，先停止 Agent、释放串口，再执行 `python tools/configure_uplink.py --port COM20 --mode pc` 并重启或启动电脑供网。该操作保留已保存的热点配置。串口编号按实际设备修改。

这里仅切换网络连接与授时。当前 RSS 资讯接口若仍指向电脑，连接热点后不能替代电脑上的采集器；完整独立晨报还需部署持续在线资讯接口。

### 2026-11-02 初轮结果（2.4GHz）

使用现有发布固件完成运行配置切换，无需重新编译或烧录。停止电脑 PPP 后，开发板重启自动取得热点地址、网关和 DNS，并记录 `MORNING_TIME source=SNTP`；用户关闭热点约 20 秒再打开，日志记录断开、自动重连尝试，并确认恢复无线地址与新的 SNTP 授时。切换前后长期人设与资讯保留。

热点上的真实文本模型请求返回 `WIFI_OK`。语音额外验证未稳定通过：记录到 ASR 音频上传中断和 DNS 超时，用户未听到唤醒问候；一次临时保持正常电源状态的试验完成了 53,760 字节 TTS 播放，但尚未确认因果或形成修复。临时 MTU、省电和诊断调整均已撤销，不将其作为持久配置发布。

因此初轮验收通过的是自动连接、断线恢复和授时，当时语音未通过。分项证据见 [初轮实板记录](bringup_logs/20261102_hotspot_auto_connect_proof.json)。

### 后续结果（5GHz）

改用 5GHz 后，关闭全部可选 TCP 调整，恢复默认发送队列、TLS 写入块和 TCP MSS。3 秒、6 秒合成静音 ASR 请求分别完整上传 128,229、256,229 字节，HTTP 200，总耗时分别为 1,473、1,897 毫秒。最终重启自动连接、SNTP 校时、自动监听正常；用户确认“你好，夕夕”得到“你好”，随后“一加一等于几”得到正确语音答案，日志确认两段 PCM 完整播放。

最终配置为 `uplink_mode=wifi`，三项诊断参数均为字符串 `"0"`，MTU 1500，保留正常电源策略。人设、当天资讯与播放记录保留，电脑 PPP 已停止。现场结果支持优先使用该 5GHz 配置，尚不能区分 2.4GHz 射频干扰、驱动或热点兼容性，也未完成长时间稳定性验证。见 [后续语音验收记录](bringup_logs/20261102_hotspot_voice_proof.json)。

## 退出与重新连接

电脑会话退出时，补丁 `0055` 先请求关闭该会话启动的 Agent，等它实际退出，再移除 PPP。补丁 `0056` 则避免默认模式在开机等待电脑、或电脑网络掉线后自行进入同步 Wi-Fi RPC。两项分别处理退出顺序和自动重连策略。

日常演示使用默认电脑模式。需要调试独立 Wi-Fi 时，可主动切换为 `wifi`，再通过热点、地址、DNS 和模型请求日志检查无线连接。

配置工具检查：`python -m unittest discover -s tests/headless -p test_configure_uplink.py`，覆盖其他配置保留、密码不进入结果、短行安全引用、临时文件／备份失败保留原文件、运行中拒绝修改及无末尾换行、异步日志交错时的串口应答。

## 语音请求保护与可选传输诊断（补丁 0067）

2.4GHz 现场默认发送队列下，约 128 KiB 的 ASR 请求在 64 KiB 处停住。仅限制队列或 TLS 写入块未恢复完整上传。8 KiB 队列、1 KiB 写入块、472 字节 TCP MSS 曾使 3 秒和 6 秒探针成功，但随后真实问答仍上传失败，不能视为修复。5GHz 使用默认参数即通过，最终未启用这些调整。

补丁 0067 包含请求保护、探针和可选诊断参数。PR #13 首版 BIN 不含该补丁，当前 2026-11-03 发布镜像已包含 0067、0068 及本地提示音功能。切换热点频段本身无需编译。若此前启用过诊断参数，先停止 Agent，使用已保存凭据恢复默认设置：

```powershell
python tools/configure_uplink.py --port COM20 --mode wifi --wifi-tx-buffer 0 --wifi-record-bytes 0 --wifi-mss 0
```

仅排查传输问题时，可显式试用 `--wifi-tx-buffer 8192 --wifi-record-bytes 1024 --wifi-mss 472`；这不是当前推荐配置。启用后 `TLS_WIFI_TX`、`TLS_WIFI_MSS` 和 `TLS_WIFI_DIAL` 显示实际参数。调整只作用于显式 Wi-Fi 模式、`wlan0` 活跃且无活跃 PPP 的连接。队列字段未配置或为 `0` 时不启用，保留原设置。

ASR 请求总预算为 60 秒；TTS 的连接／握手阶段预算最多 15 秒，完整流式音频保留最多 180 秒以容纳较长播报。DNS 仍受系统解析器重试边界约束。服务退出可取消请求；失败连接立即丢弃未发送队列，避免长期保留失败请求的数据。

固件另提供 `zhaoxi --asr-probe 1000|3000|6000` 合成静音上传探针：要求先停止自动语音并等待播放结束，不采集麦克风，不验证真实识别准确率；用于重复验证大包传输。`check_speech_bounds.py` 与原 TLS 收发检查覆盖预算、取消、退出清理、PPP 不受适配影响及小块写入的数据完整性。

## 离线验证

运行实际联网线程的 PC/Wi-Fi 策略回归：

```bash
python3 tests/headless/pc_link/check_network_policy.py \
  --sdk /root/vela/packages/ai_agent
```

该测试使用实际 `agent_main.c` 的联网线程，配置读取和网络调用为明确的测试替身；通过真实线程验证默认断网等待、PPP 后到、掉线后可关闭、模式读取一次、精确 Wi-Fi 显式启用，以及通用配置原行为。

退出所有权回归仍显式选择 Wi-Fi，确保保留“先移除 PPP 会进入同步重连”的故障对照：

```bash
python3 tests/headless/pc_link/check_owned_shutdown.py \
  --sdk /root/vela/packages/ai_agent \
  --cjson /root/vela/apps/netutils/cjson/cJSON
```

补丁已纳入 `tools/check_agent_patches.py` 的顺序检查，当前完整序列以该工具的 `SERIES` 为准。当前固件版本与整机测试结果见 [构建与验收](BES固件构建与验收.md)。
