# 朝夕答辩与视频准备

朝夕的演示主线是：在学习和工作时，随口交代一件事，设备保存事项、按要求执行，并在约定时间主动提醒。问答、备忘、待办和喝水提醒围绕这个日常过程展开，像素表情显示设备正在聆听、思考还是播报。

## 评分与作品呈现

按 2026 年 11 月 2 日核对的 [官方比赛总览](https://github.com/open-vela/docs/blob/dev-ai-contest-2026/zh-cn/contest_2026/contest_overview.md)，评分和准备重点如下。

| 指标 | 分值 | 本项目展示重点 |
| --- | ---: | --- |
| 技术难度 | 30 | BES 上的音频采集、增量语音播放、消息处理、本地存储、调度与电脑供网架构 |
| 产品创新性 | 20 | 书桌前口述事项、主动提醒、用状态表情呈现处理进度 |
| 项目完整度 | 20 | 保存回读、指定编号完成、提醒到期、正常退出与再次使用、固定源码和固件 |
| AI 开发 | 10 | 人与多个代理分工，结合实际缺陷展示定位、修复和验证；展示可复用 Skill |
| 商业潜力 | 10 | 说明使用者、摆放位置、日常使用频率、现阶段部署方式和实物成本 |
| 展示效果 | 10 | 外壳、清楚的声音、可读的表情、连贯的任务过程与架构图 |

[AI 硬件指引](https://github.com/open-vela/docs/blob/dev-ai-contest-2026/zh-cn/contest_2026/ai_hardware/ai_hardware_track_guide.md)要求自定义 Skill 和主动执行场景。可以展示智能记事本、智能提醒 Skill 源文件，以及定时任务实际到期的过程。仓库 `.claude/skills` 还保存了板级开发、调试和任务分工等开发技能。

唤醒短语按比赛要求使用“你好，openvela / Hello，openvela”；产品名称保持“朝夕”。演示电脑经 USB2UART 提供网络，BES 承担音频、模型请求、本地业务和调度。语音交互的具体过程见 [ASR 唤醒短语](ASR唤醒短语.md)。

## 四分四十秒视频安排

官方要求演示视频不超过五分钟。正式录制前先按 [现场验收](三项核心功能实板验收.md)确定实际句式、等待时间和听感，再按下面顺序录制。

| 时段 | 画面与动作 | 说明 |
| --- | --- | --- |
| 0:00–0:25 | 外壳、主板、喇叭和像素屏全景 | 介绍放在书桌上的生活事项助手，以及一个实际使用场景 |
| 0:25–0:50 | BES、电脑网络转发和 MiMo 架构图 | 指明端侧执行与云端语言服务的职责 |
| 0:50–1:25 | 唤醒后提出一个简短问题，屏幕跟随状态 | 展示问题、处理反馈和对应回答 |
| 1:25–2:05 | “帮我记一下，明天带学生证”，再查询备忘 | 展示当天保存的记录和回读结果 |
| 2:05–2:45 | 添加两项待办，按实际编号完成其中一项，再查询 | 展示准确修改和另一项的保留 |
| 2:45–3:35 | 创建三十秒提醒，等待时介绍周期喝水提醒，到期听见事项 | 展示约定时间到达后主动执行 |
| 3:35–4:05 | 正常结束、重新启动、回读备忘或待办 | 展示持续保存和再次使用 |
| 4:05–4:40 | 外壳细节、Skill、工程结构、验证结果与分工 | 介绍工程完成度和 AI 协作中的具体成果 |

画面以实物、声音和任务结果为主，电脑窗口只保留必要操作和状态。素材使用专门准备的演示事项；拍摄前收起服务凭据、真实私人备忘和其他桌面内容。时间经过或启动过程有剪辑时，用转场或字幕交代。

## 八分钟现场讲述

官方安排每队演讲八分钟、评委问答两分钟。建议演讲用一分钟介绍用户与产品，三分钟展示任务过程，两分钟解释架构与技术选择，一分钟讲验证与 AI 协作，最后一分钟说明成本、部署和后续方向。实物在旁展示外壳、接口与当前状态。

技术案例选两项即可：明确事项在本地执行，省去一次文本模型等待；任务清理修复后，十次完整启停正常完成。分别讲清交互速度和持续可用性，用对应源码、检查结果和实物行为支撑。
