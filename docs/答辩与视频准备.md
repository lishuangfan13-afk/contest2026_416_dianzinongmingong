# 朝夕答辩与视频准备

讲述主线：**随口交代，设备执行；在合适的时候提醒，在需要的时候回看。** 朝夕以 openvela 端侧 Agent 为核心，把问答、记事待办、提醒、个性化资讯和飞书联动组合成桌面生活管家。

## 技术问题的回答要点

**AI 和业务分别运行在哪里？** BES 上运行 openvela 与 ai_agent，负责声音采集、意图路由、工具、存储、调度和播放；MiMo 提供 ASR、语言模型和 TTS。电脑 PPP 承担网络网关，手机热点提供另一条联网路径。

**哪些需求直接在本地执行？** 明确的记事、待办、相对提醒和喝水控制进入 C 模块。自由表达由 Agent 与模型处理。两者共用消息与输出通道，常用事项减少一次文本模型往返。

**开机尚未联网，如何识别选网？** 使用个人语音模板，提取 13 维 MFCC，以约束 DTW 识别“有线连接”“无线连接”两个短口令。固定询问与结果提示来自带 CRC 校验的本地 ZXP 音频。

**为什么按网络选择播放策略？** 24kHz 单声道 16 位 PCM 需要每秒 48,000 字节；有线链路的供音速率决定先完整预取更适合连续播放，无线采用增量播放。长回答样本 18.88 秒音频实播 18.923 秒，最大块间隔 1 毫秒。

**如何保存事项并主动服务？** eMMC 保存备忘、待办、人设和任务，关键写入完成同步与回读；cron 在约定时间投递提醒。资讯结合人设、日期缓存和许可窗口，准备好后先询问，再播报。

**与 9 月 20 日相比，进步在哪里？** 早期圆屏原型已有 Skill、人格记忆与 cron。当前加入真实语音链路、本地执行与 eMMC 持久化、本地选网、按兴趣和日期组织的资讯，以及飞书和像素表情联动。对照来源见 [版本演进](版本演进20260920至20261104.md)。

**AI 开发留下了什么？** 除源码和工程记录外，还沉淀了开发闭环、板级启动、调试、协作、设备 Skill 编写和中文字体六个 Skill，以及产品运行的智能记事本、智能提醒 Skill。用一个实际音频案例讲清调查、修改、检查和实板复测的过程。
