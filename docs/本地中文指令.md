# 本地中文指令

产品固件通过 SDK 补丁 `0057` 和应用 `local_intent.c`，把有限的明确中文记事、待办、一次性相对提醒和喝水提醒指令直接交给本机存储。命中后不请求文本模型，不使用模型回答缓存；保存失败也直接返回实际失败，不让模型再次尝试同一操作。

自动语音先通过 VAD 收句，再由云端 ASR 识别。识别完成后，板端直接匹配这些中文指令并执行存储与调度。

## 推荐表达

| 表达 | 操作 |
| --- | --- |
| 帮我记一下明天带学生证 | 追加当日备忘 |
| 记一下：明天八点开会。 | 追加当日备忘，保留正文句号 |
| 记录一下，快递放在门口 | 追加当日备忘 |
| 帮我添加待办交作业 | 添加待办并返回实际编号 |
| 添加一个待办：带水杯 | 添加一条待办 |
| 查看待办 | 读取实际未完成待办 |
| 完成待办编号3 | 完成实际编号 3 |
| 把编号3标完成 | 完成实际编号 3 |
| 三十秒后提醒我喝水 | 保存 30 秒后的单次提醒 |
| 一分钟后提醒我起身。 | 保存 60 秒后的单次提醒，保留正文句号 |
| 请帮我在二十分钟后提醒我取快递 | 保存 1200 秒后的单次提醒 |
| 开启喝水提醒／开始喝水提醒 | 开启默认每 60 分钟一次的喝水任务 |
| 关闭喝水提醒 | 只移除喝水功能自己的任务 |
| 查询喝水提醒／喝水提醒状态 | 读取实际状态与间隔 |

允许命令前有空白，正文前可有中英文冒号或逗号。正文只去掉外层空白，保留标点与全部正文；正文超过 511 字节不会截断保存，而是回到原 Agent 流程。一次添加只保存一条原文，不把正文拆成多个事项。

记事前缀包括“请帮我记录一下／请帮我记一下／帮我记录一下／帮我记一下／请记录一下／记录一下／记一下”。待办添加前缀是源码中列出的“添加待办”“添加一个待办”“添加一条待办”“新增待办”“加个待办”及部分“帮我／请帮我”形式。查询只接受完整的“帮我查看待办／查看待办／查询待办／列出待办／待办列表”。完成使用 1～9999 的阿拉伯数字编号，只接受完整的有限句式；不会推断“刚才那个”“第三个”或多个编号。

## 问答边界

仅在语句开头匹配，不在整段文字中搜索命令。普通问题、带问号的句子、出现保守疑问词或以“吗／呢／么”结束的句子，仍交给原流程。例如：

- “一加一等于几”
- “添加待办怎么用？”
- “记录一下有什么用”
- “你能帮我记一下吗”
- “如果我说记一下会怎样”
- “把待办3标记为完成并删除4”

为了减少误操作，过滤较保守：明确要求记录的正文如果本身含“怎么／如何／什么／哪个／多少”等疑问表达，也可能交回原流程。需要逐字保存这种内容时，可以使用明确的 `zhaoxi --text note add <内容>` 命令。

hook 只处理 `voice` 和 `cli` 通道、且没有附图的消息；系统提醒、其他消息通道和附图请求保留原流程。它不解析绝对日期、复合时长或周期提醒，也不强制模型选择工具。

## 单次相对提醒

支持句首可选“请／帮我／请帮我”，随后可选“在”，接一个正整数、单位“秒／秒钟／分钟／小时”、“后提醒我”和非空正文。阿拉伯数字的总秒数范围为 1～31536000；中文数字支持 1～99 和单独的“两”，包括“十一／二十／三十／九十九”。计算单位乘法前检查上限，拒绝溢出。

正文最多 255 个 UTF-8 字节，保留完整标点，不截断。半小时、小数、负数、零、“一小时三十分钟”、明天几点、周期表达和问句均回到原流程；正文出现明显的重复或周期要求时也保守回退。明确的 `remind in <秒> <内容>`、查询和取消命令保留原接口。

自然 `remind <原句>` 命令先检查这一有限语法。命中时保留原句给本地 hook，未命中时继续使用原来的 Agent 提醒提示。创建通过现有 `cron_add_job` 完成持久保存，再读取同编号的任务，核对 epoch、正文、通道、固定会话和单次删除属性后确认。读回失败不自动重复创建。

创建确认使用当前对话的回复通道。未来任务保存 `chat_id=zhaoxi`，不会保存当前 `voice_auto_<轮次>`；到期仍走原专用提醒输出和语音失败提示音路径，当前对话结束不会令未来提醒失效。

## 喝水提醒控制

本地快捷入口只接受五种整句：“开启喝水提醒”“开始喝水提醒”“关闭喝水提醒”“查询喝水提醒”“喝水提醒状态”，允许一个“请／帮我／请帮我”前缀和句末常见标点。问句、复合操作与自定义周期不命中，例如“开启喝水提醒吗”“每半小时开启喝水提醒”“关闭喝水提醒并删除待办1”，这些仍进入原流程。

开启固定使用 60 分钟，重复同设置保持同一个任务。停止只删除 `zhaoxi_drink` 所属任务，保留用户自己的提醒。喝水核心执行后返回一份真实结果，使用原 Agent outbound 与语音轮次回复，不额外自行投递。保存失败不重试模型；取消后的轮次不播报，已保存的任务可通过状态查询核对。详细命令和自定义间隔见 [喝水提醒](喝水提醒.md)。

## 原有处理路径

SDK 在注入检查之后、原自然语言快速路径和模型之前，调用产品的纯解析 matcher。命中后再执行本机模块；执行前检查自动语音轮次是否仍有效。结果复用原有 `dispatch_response`、会话历史、outbound 和语音播放完成逻辑。自动轮次仍归到 `voice_auto` 会话，输出保留真实轮次编号。

本机操作产生 `local_note_add`、`local_todo_add`、`local_todo_list`、`local_todo_done`、`local_reminder_add` 或 `local_drink_start/stop/status` trace，后端编号为 `-1`，模型延迟为 0；本机执行耗时另记为 `duration_ms`。存储失败以失败 trace 和失败回复结束，不能变成口头成功。取消后不再播报；存储已完成后发生的取消不会倒退撤销已经保存的数据。

产品 hook 通过 weak 接口接入 SDK。应用主入口显式引用链接锚点，确保静态库中实现 hook 的对象被链接进完整固件。没有产品实现的 SDK 仍使用原模型路径。最终 ELF 应检查以下符号为大写 `T`：

```text
agent_product_local_match
agent_product_local_execute
```

## 检查

```bash
python3 tests/headless/check_local_intent.py --sdk /root/vela/packages/ai_agent
python3 tests/headless/check_drink.py --sdk /root/vela/packages/ai_agent --cjson /root/vela/apps/netutils/cjson/cJSON
```

测试使用实际应用解析器、实际 journal/TODO/cron 存储、实际 Agent 工作线程、回复分发和消息总线。模型、ASR 轮次状态、历史记录及 trace 是明确的替身。覆盖常用表达、问句和未知句误判、中文十位数字、单位和溢出、完整标点、511／255 字节边界、提醒任务真实落盘和同 ID 读回、保存失败不重试模型、取消、队列满回调、会话和轮次编号，以及产品实现缺席时的原模型路径。另用静态归档模拟完整固件的对象拉入规则，并检查两个 hook 都是强符号。喝水分支还验证五种整句与未知句边界、同设置幂等、真实 cron 文件、只移除所属任务、一次轮次回复、保存失败零模型以及取消后的回复隔离。原提醒回归继续验证查询、取消、真实调度单次投递、网络失败和音频资源回收。

整机 ELF 已确认包含两个强 hook。BES 实板通过文字入口完成中文记事、待办、相对提醒和喝水提醒的完整流程，并核对保存、到期及关闭结果。现场体验时可再使用表中的说法检查麦克风识别和语音反馈。
