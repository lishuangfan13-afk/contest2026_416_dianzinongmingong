# BES 通过电脑共享网络

朝夕使用现有 USB2UART 数据线建立 PPP 网络，让 BES 共享演示电脑的互联网连接。板子负责 DNS、TCP、TLS、模型请求、语音与业务执行，电脑负责 IP 转发。该方式方便在开发、外壳制作和答辩演示时保持同一套联网入口。

## 连接结构

```mermaid
flowchart LR
    Agent[BES 语音与业务] <--> Net[BES DNS / TCP / TLS]
    Net <-->|PPP / USB2UART| Windows[Windows 串口转发]
    Windows <--> WSL[WSL PPP 网关与转发]
    WSL <--> Internet[电脑当前互联网连接]
```

PPP 使用独立的小网段连接电脑和开发板。Windows 保持原来的上网方式，WSL 临时配置转发；BES 的云端请求沿 PPP 发出。会话结束时恢复板端 DNS、路由和控制台，并清理临时转发设置。

## 启动

已准备好的演示电脑需要 Python、pyserial 和 Ubuntu-22.04 WSL；WSL 中安装 pppd、ip、iptables，并准备 PPP/TUN 设备。完整环境和启动步骤见 [Windows 入口](../tools/pc_link/README_zh-cn.md)。

```powershell
python tools/pc_link/launch.py --check-only
python tools/pc_link/launch.py --port COM3
```

正式启动先结束旧助手、校准板上 UTC 时间，再建立 PPP 和业务控制通道。看到 `PPP_UPLINK_READY` 后，从第二个窗口执行：

```powershell
python tools/pc_link/control.py --cmd --text ask 用一句话解释DMA
python tools/pc_link/control.py --cmd --text todo add 交作业
python tools/pc_link/control.py --tasks
python tools/pc_link/control.py --cmd remind in 30 喝水
```

结束使用 `python tools/pc_link/launch.py --stop`。主机继续转发退出握手，然后释放串口。当前日常演示采用文字输入和语音播报，自动语音入口供在场体验。

## 已完成的业务测试

本方案已在实板上完成外部 DNS、HTTPS 模型请求、备忘写入回读、待办新增与指定完成、短时提醒到期和取消。11 月 1 日的本地待办改为确定性文件操作，新增、完成和读取约 0.35 秒。完整断电后，已保存的备忘和待办继续保留，正式启动入口重新授时。

当前镜像与构建方法统一见 [BES 固件构建与验收](BES固件构建与验收.md)。板载 Wi-Fi 的独立联网与连续自动语音作为后续联调内容，电脑供网保持当前演示主方案。

## 工程实现

- BES 的 `pc_link.c` 管理 PPP、路由、DNS 与控制台切换；`pc_control.c` 提供直连电脑的业务控制接口。
- apps 补丁处理 PPP 生命周期、批量串口接收、转义协商和整帧提交。
- Windows 转发以有界写入保留背压；电脑内的 TCP 两端使用 `TCP_NODELAY`，及时传送小 ACK。
- 启动、停止与状态查询具有明确的会话生命周期，程序默认保持自动监听关闭。
