# 朝夕飞书通知接口

朝夕提供固定目标的飞书通知接口，支持测试消息、通用通知和提醒文本。通知开关和目标通过设备运行配置管理，使用者显式发送后取得服务回执。

通知模块已接入产品构建和命令入口，完成 55 项本机 HTTP 协议回归。配置应用凭据与固定目标后，可通过下面的测试命令连接飞书。

## 产品命令

通过电脑供网控制入口查询通知配置、发送固定测试消息或指定文本：

```powershell
python tools/pc_link/control.py --cmd notify status
python tools/pc_link/control.py --cmd notify test manual-001
python tools/pc_link/control.py --cmd notify send manual-002 朝夕运行正常
```

`status` 只显示配置项是否已填写。每次新通知使用新的事件编号；重试同一次通知时保留原编号。设备默认关闭通知，先在运行配置中填写下表参数。

## 与原有方案的关系

AI Agent SDK 已有完整飞书机器人：读取 `feishu_app_id`、`feishu_app_secret`，后台接收聊天消息，再向来信所在的 `chat_id` 回复。当前无屏产品没有启用 `CONFIG_AI_AGENT_FEISHU`，相应高层接口是禁用状态。

本模块沿用这两个凭据配置键以及 `claw_config_get()`、`vela_https_post_json()` 和 cJSON，不启用完整机器人。没有复用旧 `feishu_send_message()` 的返回值作为成功依据：旧分段发送代码遇到 HTTP 失败仍可能返回成功，而且不验证业务 `code` 和 `message_id`。

## 运行配置

通过既有运行态配置系统设置以下值，不把实际值写进源码、资产模板或 Git。接口本身只读取配置，不修改配置。

| 配置键 | 含义 | 默认行为 |
|---|---|---|
| `feishu_app_id` | 飞书自建应用 App ID，沿用原 SDK 键 | 缺失时不请求网络 |
| `feishu_app_secret` | App Secret，沿用原 SDK 键 | 缺失时不请求网络 |
| `feishu_notify_enabled` | 只有 `1` 或 `true` 表示启用 | 缺失或其他值时关闭 |
| `feishu_notify_receive_id` | 操作者确认的固定收件目标 | 缺失时不请求网络 |
| `feishu_notify_receive_id_type` | `chat_id`、`open_id` 或 `user_id` | 缺失时使用 `chat_id` |
| `feishu_notify_auth_mode` | `legacy` 或 `oauth` | 缺失时沿用旧 SDK 的 `legacy` |

群聊使用 `chat_id`，目标需要以 `oc_` 开头；使用 `open_id` 时需要以 `ou_` 开头。机器人需要已加入目标群，应用需要已启用机器人能力并拥有发送消息权限。收件人只来自这些配置键，发送函数不接受模型或自然语言临时指定的新收件人。

原有 `feishu_user_token` 不用于这个通知模块。这里使用应用身份发送，不扩展到用户身份的其他权限。

## 调用与成功判定

```c
#include "notifications/feishu_notify.h"

struct zhaoxi_feishu_receipt receipt;
int rc = zhaoxi_feishu_notify_test("test-20261102-001", &receipt);
if (rc == 0 && receipt.accepted) {
    /* 飞书已接受该消息。 */
}
```

通用通知和提醒使用相同协议：

```c
zhaoxi_feishu_notify("设备状态说明", "status-unique-event", &receipt);
zhaoxi_feishu_notify_reminder("记得带水杯", "reminder-jobid-dueepoch", &receipt);
```

`event_id` 是调用者生成的稳定事件标识，最多 50 个 ASCII 字符，只接受字母、数字、下划线和连字符。不同通知使用不同标识，同一通知人工重试时保留同一标识；模块把它原样传给消息接口的 `uuid`。提醒可由任务编号和本次到期时间组成，不能对一个重复提醒的每次触发都复用同一个永久标识。模块不宣称无限期去重，也不会自行重发。

只有消息 HTTP 返回 200、响应 JSON 的数字 `code` 等于 0，并且包含合法非空的 `data.message_id`，接口才返回 0 并设置 `accepted=1`。HTTP 200 本身不是成功回执，错误描述文字也不作为判断依据。文本通过两层 JSON 序列化构造，中文、引号、反斜线和换行不会被拼接成请求结构。

回执只包含阶段、HTTP 状态、数字业务码、是否尝试发送、是否被接受，以及消息 ID。模块不输出凭据、目标、消息正文或原始服务端响应。

| 字段 | 用途 |
|---|---|
| `phase` | 区分配置校验、鉴权、消息发送和服务接受 |
| `http_status` | 实际 HTTP 状态；负值表示底层传输错误 |
| `api_code` | 有效数字业务码；未得到该字段时为 `-1` |
| `send_attempted` | 是否已经调用消息发送 HTTP 接口 |
| `accepted` | 是否取得明确的服务接受回执 |
| `delivery_unknown` | 消息调用后超时、响应损坏等导致无法确认结果 |

调用方必须同时检查返回值和回执。遇到 `delivery_unknown=1`，不要宣布已发送，也不要换新事件 ID 立即重发。先保留这次结果，避免因为回执丢失而重复通知。

## 鉴权与长度边界

`legacy` 沿用原 SDK 的 `open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal`，请求 `app_id`、`app_secret`，读取 `tenant_access_token`。`oauth` 使用官方新版 `accounts.feishu.cn/oauth/v3/token`，请求 `grant_type=client_credentials`、`client_id`、`client_secret`，读取 `access_token`。两种路径都检查 HTTP 状态和业务码，不从失败响应中继续取 token。首版每次通知单独取得凭据，不维护共享 token 缓存。

新版自建应用凭据采用 JWT，长度可能比旧版大。协议层允许最多 8192 字节 token，超出时拒绝处理；当前 SDK 的整个 HTTP 请求头上限是 4096 字节，所以 SDK 桥接层进一步把可发送 token 限为 3072 字节，提前返回长度错误，绝不截断 token。需要更长 token 时，应先扩展并验证底层 HTTP 头能力，或通过 `zhaoxi_feishu_io` 接入合适的服务端传输，不能只扩大本模块数组。[飞书自建应用访问凭证文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token)

本模块的文本上限是 2048 个 UTF-8 字节，App ID 上限 128 字节，App Secret 与固定目标各上限 256 字节。配置超长、类型未知或目标格式不匹配时，在消息请求之前失败，不静默裁切。

## 根代理集成位置

当前 CMake、Makefile 和产品命令入口已集成以下源文件，沿用 SDK 与 cJSON 的 include 路径：

```text
notifications/feishu_notify.c
notifications/feishu_notify_sdk.c
```

先通过明确选择的测试入口验证固定目标，再决定是否在提醒交付处调用。飞书推送应有自己的回执，不覆盖本地语音／提示音的结果；远端失败也不能伪装成本地提醒没发生。是否给定时提醒增加推送，由主流程显式决定，模块不会自行挂接。

## 离线验证与官方依据

`tests/headless/notifications/` 的测试编译实际 adapter 和 cJSON，并通过仅绑定 `127.0.0.1` 的 HTTP 服务检查鉴权请求、双层 JSON、固定目标和事件标识。失败回归验证：缺配置零请求、HTTP／业务错误不确认、非法或截断响应不确认、缺消息 ID 不确认，以及超长 token 不进入消息发送。

在已准备好的 Linux 开发环境中运行：

```bash
python3 tests/headless/notifications/check_feishu_notify.py \
  --cjson-root /root/vela/apps/netutils/cjson/cJSON
```

本轮 55 项检查通过，产生 71 次本机 HTTP 请求，启用了 ASAN、UBSAN 和 `-Wall -Wextra -Werror`。通知模块已加入 BES 完整固件；配置账号和固定收件目标后，可通过 `notify test <事件编号>` 发送测试通知并检查服务回执。

协议依据为飞书官方[发送消息 API](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[消息内容 JSON 结构](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json?lang=zh-CN)及[通用错误码](https://open.feishu.cn/document/server-docs/api-call-guide/generic-error-code)。真实账号联调使用操作者配置的应用和固定目标，并保留消息服务回执。
