# 朝夕 · 演示视频拍摄脚本

> 时长目标：约 3 分钟｜形式：手机实拍圆屏（纯屏幕特写）+ 后期配音/字幕
> 辅助机位：串口日志（左侧）与真机屏幕（右侧）左右分屏，用于解释"看不见的 AI 动作"

---

## 一、拍摄前准备（录制当天按顺序执行）

| 步骤 | 操作 | 命令 / 位置 | 预期 |
|------|------|-------------|------|
| 1 | 板子上电，确认 UI 起来 | 目视屏幕出现时钟首页 | 时钟走字、状态栏显示 WiFi |
| 2 | 挂载 `/data` | 串口 `mount -t tmpfs /tmp /data` | 无报错 |
| 3 | 部署 8 个资产 | `powershell -File tools\deploy_assets.ps1 -Port COM3` | `8/8` 全部 OK |
| 4 | 配置 LLM Key | 串口 `set_llm <host> <model> <key>` | `config_show` 显示已设置 |
| 5 | 准备干净提醒内容 | `echo "准备开始今天的演示" > /data/ai_agent/REMINDER.md` | 屏幕提醒卡更新 |
| 6 | 准备天气内容 | `echo "北京 26℃ 晴" > /data/ai_agent/WEATHER.md` | 屏幕天气卡更新 |
| 7 | 启动日志录制 | `powershell -File rec_serial.ps1 -Port COM3 -Out demo.log` | 日志实时落盘 |

> **/data 为 tmpfs，重启即清空**——每轮重拍前都要重跑第 2–6 步。

---

## 二、机位与分屏

- **主画面**：手机横/竖屏固定俯拍开发板圆屏，占满画面，避免反光。
- **左右分屏**（后期）：左侧为 `demo.log` 串口日志滚动，右侧为圆屏实拍；日志中出现关键行时给该行加高亮。
- **关键日志行**（建议高亮）：

```
[cron] Check job[1] '久坐提醒': enabled=1 ...
[tool_cron] cron_add: OK: Added one-shot job ...
[agent] [Agent]: <模型回复>
DIAG FILE reminder=...
DIAG FILE weather=...
DIAG NAV idx=1
DIAG TOUCH x=.. y=..
DIAG ALIVE <n>
```

## 三、分镜脚本

### 镜头 1｜开场（0:00–0:15）
- **画面**：圆屏特写，时钟秒级走字；缓慢推近。
- **操作**：无（首页静止）。
- **旁白**：
  > 这是一台运行 openvela 的圆屏 AI 生活管家——「朝夕」。它最大的不同是：不等你问，它主动为你做事。

### 镜头 2｜首页导览（0:15–0:50）
- **画面**：圆屏首页全景；可用手指依次轻点/指示各区块（或后期加箭头标注）。
- **操作**：静止展示首页（状态栏 / 时钟卡 / 问候语 / 天气卡 / 提醒卡 / 导航胶囊）。
- **旁白**：
  > 首页是一块 454 乘 454 的圆形 AMOLED 屏。顶部状态栏实时显示 WiFi 与 AI 状态，中间是走字的时钟和日期，下方天气卡片展示实时天气，提醒卡片展示当前待办，底部是导航胶囊。所有元素都按内切圆安全区布局，圆屏四角没有任何裁切。

### 镜头 3｜三屏与触摸（0:50–1:20）
- **画面**：左右分屏（左日志 / 右屏幕）。
- **操作**：
  1. 点底部「对话」→ 切到对话页（日志出现 `DIAG NAV idx=1`）
  2. 用触摸键盘输入「今天天气怎么样」→ 点「发送」（日志出现 `DIAG TOUCH`、`INPUTDBG:`）
  3. 点「设置」→ 切到设置页（`DIAG NAV idx=2`），展示网络/待办/运行时间
  4. 左滑回首页（`DIAG NAV idx=0`）
- **旁白**：
  > 左右滑动或点按导航，可以切换三个页面。对话页内置触摸键盘，可以直接打字输入；设置页展示网络状态、待办数量和运行时长。左边日志里的 DIAG NAV 和 DIAG TOUCH，就是每一次切屏与触摸的实时记录。

### 镜头 4｜主动推送（核心）（1:20–1:55）
- **画面**：左右分屏。日志滚动到 cron 触发；右侧提醒卡内容发生变化。
- **操作**：
  1. 提前将演示 cron 任务设为短间隔（见第四节）
  2. 镜头对准屏幕等待任务触发（日志出现 `[cron] Check job` → `DIAG FILE reminder=...`）
  3. 屏幕提醒卡在 2 秒内自动刷新
- **旁白**：
  > 现在展示核心能力——主动服务。设备端有四个定时任务：每日简报、久坐提醒、饮水提醒、早安闹钟。时间一到，cron 引擎自动触发，把提醒写入文件，界面两秒内刷新上屏。左边是串口日志，可以看到任务被触发、文件被写入、UI 读取到新内容的完整链路——全程无需用户任何操作。

### 镜头 5｜自然语言 + 大模型闭环（1:55–2:30）
- **画面**：左右分屏，重点高亮 `[Agent]:` 与 `[tool_cron] cron_add`。
- **操作**：
  1. 串口执行：`ask 30秒后提醒我喝水`
  2. 日志出现 `Sent to agent:` → `[Agent]: <回复>` → `[tool_cron] cron_add: OK`
  3. 等待约 30 秒，提醒准时上屏（`DIAG FILE reminder=...`）
- **旁白**：
  > 除了定时任务，也可以用自然语言下指令。我们对它说"三十秒后提醒我喝水"，这句话通过网络送到小米 MiMo 大模型，模型理解后自动调用 cron 工具，创建了一个一次性任务。三十秒后任务触发，提醒准时出现在屏幕上。从对话、到执行、到上屏，AI 完成了完整的闭环。

### 镜头 6｜架构与 AI 开发（2:30–2:50）
- **画面**：后期叠架构图 / 补丁列表 / 日志目录截图（可选）。
- **旁白**：
  > 整个项目基于开源 openvela 和 ai_agent 框架，我们提交了六个框架补丁，让它在这个平台上真正可用；界面、脚本、技能与文档约九成由 AI 辅助完成，全部会话日志已按官方规范归集入库、可稽核。

### 镜头 7｜收尾（2:50–3:00）
- **画面**：回到首页时钟特写，画面渐暗。
- **旁白**：
  > 朝夕，一个会主动关心你的 AI 管家。下一步，我们将加入语音唤醒与播报，让它从"主动说"走向"随时答"。

## 四、演示用短间隔 cron 任务

正式 `cron.json` 的最短间隔为 90 分钟，无法在镜头前等待。**演示当天**通过大模型工具或串口临时创建短间隔任务：

**方式 A（推荐，最能体现 AI 能力）**：镜头 5 用 `ask 30秒后提醒我喝水` 让 LLM 调 `cron_add` 创建 `at` 任务。

**方式 B（备用）**：若模型未稳定触发工具调用，则用串口直接写 `REMINDER.md` 模拟触发，旁白如实说明为手动触发。

> 演示结束后**务必删除临时任务**，避免污染正式 `cron.json`。
