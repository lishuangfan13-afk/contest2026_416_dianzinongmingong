# 2026-11-02 唤醒与晨间资讯验收

本轮交付开机唤醒、60 秒会话空闲退出、长期人设和每日晨间资讯。最终 AP 已构建并烧录到 BES2800BP，源码、SDK 补丁、测试与发布固件一同保存。

## 行为

开机后自动检测“你好，夕夕”及常见同音转写，播报“你好”后进入提问。问候及每次回答播完后获得 60 秒空闲窗口，到期回到等待唤醒；采集、ASR、思考和播放期间暂停空闲计时。

人设保存到 `/emmc/zhaoxi/config/USER.md`，更新经过临时写入、同步、回读和替换，保留上一版；普通记忆与新闻分别保存。首轮使用的人设为“热爱 AI、电子技术的大学生，偏好中文、开源项目与动手实践。”，可用 `profile set` 更新。

联网或恢复连接后授时，按北京时间 06:55 预取、07:00 起在空闲时询问；当天错过七点可在 22:00 前补取。电脑随供网启动官方 RSS 采集器，板端按人设生成有来源的中文摘要、先可靠保存，再询问许可。拒绝或 60 秒无明确回应都不播放，重启不沿用旧许可；同批次最多自动询问一次，可显式请求复播。

## 构建与软件检查

最终镜像为 [nuttx_ap_headless.bin](../firmware/headless_pc_link/nuttx_ap_headless.bin)，大小 1,362,288 字节，SHA-256 为 `0f4078aafd755bc0cf48d246c02736cbe5493bb05edcc6f4fe49884fd5474e64`，仅烧录 AP 地址 `0x30190000`。来源哈希和分项状态见 [manifest](../firmware/headless_pc_link/nuttx_ap_headless.manifest.json)。

新增模块首次导致 CMake 刷新并扩大编译任务，后续修正复用缓存增量编译；最终标点兼容修正执行 16 项构建任务，没有清空构建目录。SDK 的 51 项补丁已按顺序回放并与实际构建源码一致。

通过以下软件检查，C 检查启用 ASan／UBSan：

- 实际 C 存储及故障注入：短写、同步／替换失败保留旧文件、UTF-8 校验、批次恢复、跨天去重与清理。
- 实际晨间工作线程：保存后询问、拒绝／沉默／迟到同意不播放、许可绑定批次、重启不复用、唤醒抢占、退出释放音频。
- 摘要来源约束：标题和链接固定，未知／重复候选与过期内容拒绝，空候选不调用模型。
- 实际 TLS BIO：阻塞读、满发送缓冲区、总时限与立即取消；已有 TLS 收发和响应解析检查继续通过。
- 自动语音状态机和唤醒回归：问候先于问题、录放互斥、停止取消、空闲到期及边界输入。
- 5 项 RSS／采集器检查、33 项电脑启动器检查。
