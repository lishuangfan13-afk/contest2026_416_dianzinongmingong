# 自动语音终端

2026-11-01。0034～0037 在原 SDK 的音频、ASR、消息总线和 TTS 上增加本机语音端点检测及回合边界。用户主动开启后，由板子循环等待说话、检测句末停顿、识别、处理、播报和重新等待。开机默认关闭；电脑转发程序只提供网络，不负责逐句启动和停止录音。日常规则见 [语音交互收尾](语音交互收尾.md)。

## 本机判断

| 项目 | 当前实现 |
| --- | --- |
| 输入 | 16kHz、16位、单声道 PCM，沿用 BES 实际采集增益和高通设置 |
| 检测帧 | 20ms；按实际收到的 PCM 拼满一帧后计算 |
| 环境校准 | 初次启动采集 1 秒环境声音，后续复用并缓慢更新噪声基线 |
| 能量 | 帧内样本绝对值平均值；阈值为噪声基线的 3 倍加 100，最低 180 |
| 噪声跟踪 | 等待状态下对低于阈值的帧缓慢更新基线 |
| 发声起点 | 连续 60ms 超过阈值 |
| 片前缓存 | 保留起点前最多 300ms，降低漏掉第一个字的概率 |
| 最短有效发声 | 至少 240ms；较短的撞击或片段丢弃，不调 ASR |
| 句末停顿 | 约 1200ms 后自动封句 |
| 最长句子 | 最多 12 秒，同时受实际 PCM 缓存容量限制；超长整段及残句拒绝，等静音后接下一句 |
| 识别时机 | 关闭采集设备后，才调用批量 ASR |

这是能量与时间规则，不是经过远场、口音和多噪声环境训练或验收的语音分类器。安静、拍手、近距离人声、背景声音及阈值仍需在真实板子上对照。启动校准期间应先保持约一秒安静；当前不支持播报中插话。

## 回答与播报的配合

有效识别文字进入现有 Agent 消息总线，通道为 `voice`，每轮带独立代号，持久对话历史统一为 `voice_auto`。提交后暂停采集，等待这轮最终回答；忙时说话不缓冲、不拼接。

`voice_channel_speak()` 的包装会在任何播报前暂停并关闭自动采集，避免把喇叭的声音重新识别成提问。播放完成后留出 600ms 冷却。提醒等其他播报只暂停音频，不结束尚在等待的问答。

出站调度器必须按本轮代号核对并收束最终消息。成功、TTS 失败、出站冷却或队列丢弃，都需要结束对应轮次；普通提醒不能结束问答。过期或已停止轮次不能冒充当前轮。完成后播放可说话短提示，复用噪声基线接收下一句。

ASR 失败、设备读取失败或消息投递失败会输出本机状态，并尝试恢复。180 秒没有收到最终完成回调时停止监听，避免旧请求未完成时继续接受新指令。可选弱钩子 `voice_channel_auto_feedback(int event)` 用于本机可说话、收句和错误短提示，不依赖云端合成；调用前释放采集设备。

## 产品接口

| 接口 | 约定 |
| --- | --- |
| `voice_channel_auto_start()` | 启动一次，已运行时幂等；与手动 PTT 互斥 |
| `voice_channel_auto_stop()` | 请求取消并中断当前采集；不会假装已结束正在进行的网络工作 |
| `voice_channel_auto_status(output, capacity)` | 返回启用/运行状态、中文阶段、噪声、阈值、处理帧数、句子数、ASR 次数、短片段拒绝数及上一句字节数；不输出 PCM |
| `voice_channel_auto_reply_done()` | 仅最终 `voice_auto` 出站消息的完成回调 |

退出电脑联网会话或停止 Agent 时，先请求 `auto_stop()`，再等运行线程真正结束。自动线程同时检查已有 Agent 停止标志，不会在 Agent 退出后继续提交新提问。

## 已完成验证与实板边界

`tests/headless/voice/check_auto_voice.py` 编译实际 SDK 的 `voice_channel.c`，音频和云服务使用明确的替身。ASan/UBSan 下已经验证：静默不调 ASR/API；短撞击拒绝；停顿封句；持续发声的最长句和容量上限；ASR 失败恢复；播报先关闭采集；普通提醒不结束当前轮次；最终回答回调后自主重听；停止后设备打开/关闭次数匹配。

手动采集的启动顺序与失败清理回归仍通过，真实 BSP ARM 参数下语法检查通过。这些结果不是实际麦克风识别率、真实端点延迟、云端接口成功或扬声器听感的验收。实际固件烧录与真人连续多轮对话应另记证据。
