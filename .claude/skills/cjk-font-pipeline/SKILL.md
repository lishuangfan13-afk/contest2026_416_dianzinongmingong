# LVGL 中文字体流水线

## 何时使用

- 中文显示全部变成"豆腐块"（空心方框）
- UI 改了文案，担心新字缺字形
- 固件体积紧张，不能上全量中文字体

## 问题本质

LVGL 内置 Montserrat 字体**不含 CJK**，直接写中文全部渲染为豆腐块。全量中文字体动辄数 MB（固件总共才 2.3MB），必须做**子集**——而子集的敌人是"改了文案忘了加字"。

## 流水线（tools/gen_cjk_fonts.ps1 + check_cjk_coverage.ps1）

```text
① 扫描提取    从 UI 源码 + 运行时数据文案（天气/提醒等动态文本）
              自动提取所需汉字集合
② 生成子集    lv_font_conv 生成 4 个尺寸的中文子集字体（本项目 262 字）
③ 覆盖率闸门  构建前校验"文案用字 ⊆ 字体子集"，缺字即 FAIL
```

**关键设计：把"缺字"从运行期问题变成构建期错误。** 没有这个闸门时，改一行文案就可能悄悄引入豆腐块，要到烧录上板才肉眼发现（一次烧录 ~40 分钟构建成本）；有了闸门，缺字在本地几秒内报错。

## 覆盖范围的两个来源（易漏第二个）

1. **源码静态文案**：UI 代码里写死的标签、按钮、提示语
2. **运行时动态文案**：Agent 写入数据源文件的内容（如 `WEATHER.md` 的城市名、天气状况词、`REMINDER.md` 的提醒话术）

只扫源码会漏掉动态文案——城市名"上海"、"阴"这类字就是从运行时数据清单提取的。

## 红线

- 改任何 UI 文案后必须跑一次覆盖率校验，FAIL 就把缺的字加进提取清单重新生成
- 不要手工维护字体子集清单——由脚本从源码提取，人工维护必然漂移
- 提醒 Skill 的输出格式约束（见 `device-skill-authoring`）也影响用字范围，两者要一起考虑
